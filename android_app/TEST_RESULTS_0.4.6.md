# 0.4.6 · 앱·애드온 사이트 선택·달력 동일 적용

- 앱 0.4.6 / versionCode 12, HA 애드온 2.15.11. 최소 지원 코드 5 유지, 선택 업데이트. preview 표기 없음.
- 양쪽은 동일한 site-choice.js로 사이트 추가·선택한 목록·삭제·드래그·키보드 정렬을 제공한다. 공통 소스 동일성 테스트 포함.
- 일반 예약은 선택한 전체 숙박 기간의 동일 사이트 가능 여부가 확인된 곳만 추가 목록에 표시한다. 일별 3곳 + 3곳이지만 공통 연박 사이트 0곳인 사례는 두 화면에서 후보 없음으로 검증했다. 날짜별 개수는 연박 후보 판정에 사용하지 않는다.
- 다른 기간의 응답·조회 실패는 후보로 사용하지 않는다. 현재 기간에 불가로 확인된 이전 선택은 해제한다. 오픈 전 예정은 전체 사이트를 후보로 허용하고 취소 대기는 마감 사이트도 감시 후보 지정 가능하다.
- 두 달력 모두 날짜별 가능 수·마감·예정·미확인 표시 및 퇴실일 제외 규칙 유지. 애드온의 이전 입실·박수 표시 설정은 최초 한 번 입실·퇴실로 전환하며 이후 명시적으로 끈 선택은 유지한다.
- 네이티브 UI의 날짜 변경·저장 입력 복원·화면 재진입은 조건별 60초 중복 방지와 진행 중 작업 보호 하에 읽기 전용 전체 기간 조회를 요청한다. 다인 입력 중에는 조회 결과 갱신으로 이름 입력칸을 재생성하지 않는다.
- 브라우저 앱 UI 7개, 애드온 관련 달력·선택·초안·설정·실제 로컬 HTTP API 회귀 30개 통과. 기존 선택·정렬·저장 회귀도 새 선택기에 맞춰 갱신했다.
- 애드온 전체 220개를 실행해 219개가 첫 실행에서 통과했다. 행을 추가하지 않아도 항상 목록이 있다고 전제하던 글꼴 UI 테스트의 준비 과정을 새 선택기에 맞춰 수정하고, 해당 설정·갤러리 묶음 3개를 재실행해 모두 통과했다. 추가 엔진·조회·기간·일정·마감 관련 묶음 65개도 통과했다.
- 실제 Android 에뮬레이터에서 공통 스크립트 허용, 전체 기간 필터, 추가의 실제 Plan 반영, 공통 연박 0곳 처리, 예정 14개 후보, 날짜 표시 및 실제 예약 서비스 미실행 등 8개 검증 통과.
- assembleDebug / assembleDebugAndroidTest / lintDebug 성공. lint 오류 0, 기존 경고 4개. 실제 캠핑장 예약/취소는 검증에서 실행하지 않았다.
