## 변경 사항

- 취소 자리 감시는 명시적으로 시작한 활성 대기 일정이 있을 때만 실행한다. 예약 취소를 자동으로 수행하는 기능은 아니다.
- 기본·최소 감시 간격 10분, 설정 범위 10~60분. 이전 60초 설정은 600초로 보정한다.
- 조회 사이에는 CPU wake lock을 해제하고 알람으로 다음 조회를 예약한다. 감시 중 상태 알림은 유지한다.
- 미래 시각 예약은 서비스·지속 알림 없이 알람만 등록한다. 지정된 엔진 시작 시각에 서비스를 시작한다. 미리 최종 제출하는 방식은 아니다.
- 결과 확인이 필요한 제출은 재전송하지 않는 안전 동작을 유지했다.

## 자동 검증

읽기 전용 전용 에뮬레이터(Android 17 / arm64 / 16KiB)에서 최종 소스의 **43개 검증 항목 통과**. 실제 사이트 예약·취소 전송 없이 앱 내부 모의 페이지만 이용했다.

기존 암호화, 경로 차단, 영수증 대조, 429 재전송 금지, 중지·복구 안전성에 추가해 다음을 확인했다.

1. 기본 간격 600초, 599초 거부, 600초 허용, 기존 60초 설정의 600초 전환.
2. 빈 객실이 없으면 다음 조회 시각이 10분 이후로 저장됨.
3. 조회 사이 CPU wake lock이 해제됨.
4. 이른 알람이 와도 재조회하지 않음.
5. 다음 시각이 된 감시는 한 번 조회 후 다시 최소 10분 간격으로 대기함.
6. 감시 중지 후 남은 알람이 와도 조회하지 않음.
7. 미래 시각 대기 중 실행 서비스·지속 실행 알림·CPU wake lock 없음.
8. Activity 종료 및 강제 Doze 상태에서 정확한 알람으로 모의 예약 엔진이 깨어나 완료됨.
9. 조용히 대기하는 미래 일정을 서비스 시작 없이 중지할 수 있음.

주기 재개 테스트는 모의 일정의 다음 실행 시각을 테스트 코드에서 만료시켜 검증했다. 실제 폰에서 10분마다 장시간 실행한 배터리·절전 실측 결과는 아니다. Android의 절전 정책 때문에 실제 조회 간격이 10분보다 길어질 수 있다. 전원 꺼짐·강제 중지 상태의 실행을 보장하지 않는다.

## 실제 사이트 제한

이 버전에서는 실제 사이트에 추가 예약·취소 요청을 보내지 않았다. 이전 0.1.0의 개발 환경 읽기 전용 조회는 HTTP 403으로 중단됐다. 따라서 현재 APK는 여전히 내부 엔진 검증용이며 실제 사이트 예약 성공은 검증하지 못했다. 사용자 폰에서 ‘객실 조회만’으로 접속부터 확인해야 한다. 차단 우회는 구현하지 않았다.
