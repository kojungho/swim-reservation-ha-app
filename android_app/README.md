# 쉼오지 폰 예약 — 독립 안드로이드 앱

## 현재 버전: 0.3.0-preview (2026-10-25)

새 공식 사이트 `https://www.swimozicamp.com/camp/`용 독립 실행 APK입니다. HA 애드온 코드·운영 설정은 변경하지 않습니다. 아래 0.2.0 설명은 이전 버전 기록이며 **구사이트 접속 경로·필수 생년월일 정보는 더 이상 적용되지 않습니다.**

- 설치: `dist/swim-phone-0.3.0-preview.apk`. 기존 앱과 같은 디버그 서명으로 업데이트 설치합니다. 개인 검증용이며 제품/스토어 출시판은 아닙니다.
- 지원 실행: 단독 예약 우선순위 중 사이트 하나, 시각 예약, 취소 대기(최소 10분), 한 번에 활성 일정 하나. 다인·다중·앱 내 예약내역/월별 수집·서버 시간 동기화·동적 사이트 번호 추가는 아직 미지원입니다. 해당 메뉴는 미지원 또는 공식 사이트 연결로 표시합니다. 현재 번호는 검증된 1~14이며 알 수 없는 번호·충돌은 중지합니다.
- 실행: 지정 시각에 `book.php`를 열고 사이트·기간·인원·폼 전송 주소·보안값을 대조한 후 예약자 정보·무통장·필수 약관을 한 번에 입력합니다. 필수 동의만 체크하며 선택 마케팅 동의/숨김 보안값은 바꾸지 않습니다. 사전 입력·예약 제한 우회는 하지 않습니다.
- 생년월일은 사용하지 않습니다. 입금자명은 선택이며 비우면 예약자명, 인원은 성인 1~2명, 도착 시간·요청사항은 선택입니다. 결제는 무통장 신청만 지원하며 입금은 직접 해야 합니다.
- 403·429·시간초과·미확인 완료는 자동 재시도하지 않습니다. 명확한 마감 안내만 다음 우선순위로 넘어갑니다. 오픈 전 안내는 제출 없이 중지합니다. 제출 전 내구성 마커를 저장하고 영수증의 번호·예약자·사이트·기간·박수·인원·입금 대기를 대조합니다.
- 일반 입력은 암호화된 초안으로 자동 저장합니다. 완료한 실행과 같은 초안만 초기화하며 새로 편집한 초안은 보존합니다. 플로팅 초기화는 초안만 지우며 저장 예약자·등록 일정·실제 예약을 삭제하지 않습니다. 오래된 구사이트 일정은 자동 실행하지 않고 다시 확인·등록해야 합니다.
- 업데이트: 실행 시 하루 한 번 공개 `android_app/update.json`을 확인하며 설정에서 수동 확인할 수 있습니다. 새 버전이면 GitHub APK 다운로드를 안내합니다. 설치는 사용자가 Android 설치 화면에서 승인합니다. 개인정보·HA 토큰·예약 사이트 쿠키는 업데이트 서버에 보내지 않습니다. 실행/대기 중에는 업데이트를 제안하지 않습니다. 배포마다 versionCode 증가·같은 서명의 APK·manifest 동시 갱신이 필요합니다.
- 미래 실행 시각 전에는 알람만 등록하고 지속 알림/엔진은 켜지 않습니다. 실행·취소 감시 중에만 서비스 알림을 유지하고 조회 사이에는 CPU 잠금을 해제합니다. 화면 잠금과 전원 꺼짐은 다릅니다. 전원 꺼짐·강제 중지·제조사 절전 제한에서는 무중단/정시 실행을 보장하지 않습니다.
- 실제 사이트 예약은 개발 테스트에서 보내지 않습니다. 사용자 실기기 잠금·절전 검증과 실제 예약 성공은 별도 확인이 필요합니다. HA와 같은 예약을 동시에 실행하지 마세요.

## 이전 0.2.0-preview 기록

버전: 0.2.0-preview · Android 8.0(API 26) 이상 · 개인 설치/검증용 디버그 서명 APK

기존 HA 애드온의 코드·배포·설정·실행 상태를 바꾸지 않는 별도 프로젝트입니다. HA 서버 주소나 계정 없이 폰에서 실행합니다. 아직 실제 예약에 바로 투입할 완성판은 아닙니다.

## 중요한 현재 제한

- 모의 사이트를 이용한 폰 내부 엔진·백그라운드·강제 절전 테스트는 수행했습니다.
- 개발 에뮬레이터의 실제 사이트 읽기 전용 조회는 HTTP 403으로 중단됐고, 사용자 제공 사진에서도 폰 앱 조회와 일반 브라우저 접속 모두 403이 확인됐습니다. 앱 단독 문제인지, 사이트·앞단 장비의 제한인지 응답만으로 확정할 수 없습니다. 예약자 정보 부족이라고 단정하지 않습니다. 실제 예약 검증은 완료하지 못했으며 차단을 우회하거나 인증서를 무시하지 않습니다.
- 실제 예약/취소 요청은 테스트하지 않았습니다. 자동 예약에 사용하기 전에 반드시 읽기 전용 조회와 폰 잠금 상태의 모의 테스트부터 하세요.
- 예약자와 일정은 각각 최대 20개까지 폰에 저장합니다. 실제 실행은 활성 일정 1개, 예약자 한 명의 객실 하나 예약입니다. HA의 다인·다중 실행·사진 갤러리·앱 내 예약 취소 관리·월별 현황 수집은 아직 이식하지 않았습니다. 해당 메뉴는 지원하지 않음을 표시하고 실행시키지 않습니다.
- 지정 시각은 **객실 조회부터 엔진을 시작하는 시각**입니다. 미리 준비한 폼의 최종 제출 시각을 서버 시간에 정밀 동기화하는 HA 기능과는 다릅니다. 폰의 자동 날짜·시간 설정을 사용하세요.

## 설치와 확인 순서

1. `dist/swim-phone-0.2.0-preview.apk`를 폰으로 옮겨 설치합니다. APK 설치는 폰에서 사용자가 직접 진행합니다. 기존 0.1.x와 같은 서명으로 업데이트 설치할 수 있습니다.
2. 오른쪽 위 메뉴의 **설정 → 알림 허용**을 누르고 안드로이드 권한 창에서 허용합니다. 배터리·알람 권한과 모의 테스트도 설정 화면으로 이동했습니다.
3. ‘배터리 설정 열기’는 시스템 배터리 최적화 목록을 직접 엽니다. 지원하지 않는 기기는 앱 정보로 이동합니다. ‘배터리 예외 허용 요청’은 별도 권한 요청입니다. 상태가 이미 ‘허용’이면 다시 요청할 필요가 없으며 이 경우 안내와 설정 열기 버튼을 표시합니다. 제조사별 ‘절전 예외/절전 안 함’ 설정도 확인하세요. 앱이 설정을 몰래 변경하지 않습니다.
4. 시각 예약 또는 취소 대기 감시를 쓰려면 ‘정확한 알람 설정’도 허용합니다.
5. 먼저 **모의 예약 엔진 테스트**를 누릅니다. 실제 사이트에는 접속하지 않습니다. 12초 대기 중 화면을 잠갔다가 알림/기록의 ‘[모의] 완료 영수증 대조 성공’을 확인하세요.
6. 단독 예약 화면에서 입실일·박수만 입력하고 객실 선택의 **새로 고침 · 실제 객실 조회**를 실행해 폰에서 접속이 되는지 확인합니다. 이 버튼은 다음 단계 폼을 전송하지 않습니다. 403·429가 보이면 중지하고 사이트 안내를 따르세요.
7. 실제 실행은 공식 사이트 약관을 직접 확인하고 예약자 정보·객실 우선순위를 입력한 뒤 동의 및 시작 확인을 거쳐야 합니다. **같은 예약을 HA와 폰에서 동시에 실행하지 마세요.**

## 사이트 선택과 공식 페이지

- ‘사이트’는 쉼오지 캠핑 구역/객실을 의미합니다. 다른 캠핑장 웹사이트를 연결하는 기능은 아닙니다.
- 애드온과 같은 객실 선택 목록에서 하늘존 8개·산맥존 6개를 체크하고, 손잡이 드래그 또는 화살표로 우선순위를 정합니다. 기존 저장된 객실명·순서도 보존합니다.
- 목록은 기존 애드온의 구성 목록이며 실시간 빈자리 표시가 아닙니다. 이 버전은 우선순위 중 빈 객실 하나만 예약하며 다인·다중 예약 기능까지 이식한 버전은 아닙니다.
- 공식 예약 페이지는 선택한 입실일의 한국 시간 `adaystart`를 포함해 일반 브라우저로 엽니다. 예약 내역 조회는 별도 버튼입니다. 예약자 정보를 URL로 전송하지 않습니다.
- 날짜 없는 기존 버튼을 보완했지만, 앱의 날짜 포함 조회도 403이었으므로 이 변경을 403 해결이라고 주장하지 않습니다. 공식 페이지 접근 권한은 사이트 운영자 확인이 필요할 수 있습니다.

## 애드온과 같은 화면 구성

- 애드온의 HTML 구조·CSS와 달력 함수를 APK에 함께 넣었습니다. HA 웹페이지를 원격으로 여는 방식이 아니며 UI에 HA 주소·서버가 필요하지 않습니다. 기존 애드온 파일은 변경하지 않았습니다.
- 같은 9개 메뉴, 날짜·시각 → 예약자 → 객실 → 저장 이력 순서로 구성합니다. 설정에는 글자 크기, 입실·퇴실 선택, 플로팅 위치·크기, 배치도 아이콘 등 표시 옵션을 제공합니다.
- 입실일은 같은 월별 달력으로 선택합니다. 설정의 ‘입실·퇴실일 선택’을 켜면 두 날짜로 1~6박을 자동 계산합니다. 취소하면 기존 날짜가 유지되며 실행 시각은 같은 달력에서 시·분·초를 지정합니다.
- 예약자 정보에서 최대 20명을 저장·수정·삭제하고 예약 화면의 저장 목록에서 불러올 수 있습니다. 일정 이름을 지정해 최대 20개를 등록·불러오기·수정·삭제합니다. 등록만으로 예약하지 않으며 목록의 시작 또는 즉시 예약을 눌러 별도 네이티브 확인 창을 거칩니다.
- 일정은 등록 당시 예약자·객실·시각을 복사해 저장합니다. 이후 예약자를 수정·삭제해도 등록된 일정은 바뀌지 않습니다. 동시에 실행하는 일정은 1개입니다.
- 서버 동기화 시계는 아직 지원하지 않아 상단을 ‘폰 시간’으로 명확히 표시합니다. 기본 배치도는 앱에 포함하며 HA에 업로드한 사진과 별도입니다. 예약 조회와 월별 현황은 공식 사이트 연결만 제공합니다.
- UI는 앞에 떠 있는 동안 폰 내부 상태만 갱신합니다. 날짜 변경·메뉴 이동으로 사이트에 자동 조회하지 않습니다. 실제 사이트 주기 조회는 시작한 취소 대기 일정에서만 최소 10분 간격으로 수행합니다.

## 실행 구조

- `MainActivity`: APK에 포함된 로컬 UI 전용 WebView입니다. 지정한 내부 origin의 파일만 제공하고 외부 페이지·파일·서브프레임·네트워크 요청을 차단합니다. 로컬 UI에만 제한된 JSON 인터페이스를 제공하며 실제 사이트를 실행하는 엔진 WebView에는 인터페이스가 없습니다. UI의 DOM 저장소·파일 접근은 비활성화하고 개인정보는 네이티브 암호화 저장소에만 보관합니다.
- `PhoneRepository`: 기존 draft를 보존해 읽고 예약자·일정·UI 설정을 별도 Keystore AES-GCM vault에 저장합니다. 복호화 실패 시 자동 초기화하지 않습니다.
- `PlanScheduler`: 미래 시각 예약은 암호화된 일정과 알람만 등록합니다. 시각 대기 중에는 실행 서비스·지속 알림·주기 조회가 없습니다. 실행 시각에 서비스를 켭니다. 대기 중 중지는 서비스 없이 알람을 해제합니다.
- `ReservationService`: 예약 실행 또는 명시적으로 시작한 취소 대기 감시 중에만 알림을 유지하는 포그라운드 서비스가 실제 엔진을 소유합니다. Activity가 종료돼도 서비스와 엔진은 독립적으로 실행됩니다.
- `PhoneEngine`: 서비스 내부 Android WebView에서 사이트의 실제 폼·JavaScript를 처리합니다. 단순한 HA 웹 화면 래퍼가 아닙니다. Node.js/Chromium 서버나 외부 실행 서버가 필요 없습니다.
- `assets/engine.js`: 기존 HA의 개인정보 필드 매칭, 예약 행/예약자 대조 로직을 이식했습니다. 원격 페이지에 Android JavaScript 인터페이스를 노출하지 않습니다.
- `AlarmReceiver`: `setExactAndAllowWhileIdle`로 대기 중 CPU를 계속 깨워두지 않고 지정 시각에 엔진을 시작합니다. 권한이 없으면 시각 예약을 거부합니다. 10초 넘게 늦게 시작된 예약은 자동으로 제출하지 않습니다.
- 취소 자리 감시는 등록하고 시작한 대기 일정이 있을 때만 수행합니다. 기본·최소 간격은 **10분**이며 설정에서 10~60분의 정수로 변경합니다. 기존 1분 설정은 10분으로 보정합니다. 대기 일정이 없거나 중지한 후에는 감시하지 않습니다.
- 실제 조회/폼 처리 중에만 시간 제한이 있는 partial wake lock을 갱신하고, 취소 대기 감시의 조회 사이에는 CPU 잠금을 해제합니다. 이때 서비스 알림은 유지합니다. 최소 10분 경과 후 알람으로 깨우되 절전 정책 때문에 더 늦어질 수 있습니다. 입실일 한국 시간 00시에는 조회 없이 감시를 종료합니다.
- 최종 클릭 전에 내구성 있는 제출 마커를 기록합니다. 429·전송 후 연결 실패·영수증 불일치·처리 중 프로세스 종료 시 자동 재제출하지 않습니다. 공식 예약 내역 확인 후 사용자가 명시적으로 잠금을 해제해야 합니다.
- 재부팅/앱 교체 시 미래 시각 알람만 복원합니다. 감시/이미 실행 중이던 예약은 자동 재실행하지 않습니다. 강제 종료 후에는 앱을 다시 열어 상태를 확인하세요.

화면 꺼짐과 전원 꺼짐은 다릅니다. 전원 꺼짐·방전 시 실행할 수 없으며, 제조사 절전 정책·사용자 강제 중지·네트워크 단절·Android 시스템 제한에서 무중단/정시 실행을 보장하지 않습니다. 실기기 장시간 테스트가 필요합니다.

## 개인정보·접속 안전

- 예약자/일정은 Android Keystore AES-GCM 키로 암호화해 앱 내부에 저장합니다. 앱 삭제 시 정보와 키도 삭제됩니다.
- 클라우드 백업·기기 간 데이터 추출은 비활성화했습니다. 분석/광고/HA API 호출을 추가하지 않았습니다.
- 로그에는 예약자명·전화번호·생년월일·응답 본문·임의 헤더·쿼리를 기록하지 않습니다.
- WebView 쿠키는 해당 앱만의 세션이며 매 실행 전 초기화합니다. 파일/콘텐츠 접근·혼합 HTTP·제3자 쿠키·외부 예약 경로를 차단합니다. 실제 사이트가 비보안 경로나 다른 호스트로 이동을 요구하면 자동으로 우회하지 않습니다.
- 예약 완료는 HTTP 200이나 완료 문구만으로 판정하지 않고 예약자·휴대폰·예약 식별값·객실·입실일·박수를 대조합니다.
- 모든 폼 전송을 자동으로 되풀이하지 않습니다. 자동 확인창 승인은 사전에 동의한 최종 단계의 제한된 예약 확인 문구에만 적용하며, 취소/추가 약관 등 알 수 없는 확인창은 거부합니다.

## 빌드

JDK 17, Android SDK Platform 36 / Build Tools 35.0.0 이상이 필요합니다. `ANDROID_HOME`을 설정하거나 Android Studio에서 SDK 위치를 지정합니다. Gradle Wrapper 8.11.1의 배포 파일 SHA-256을 고정했습니다.

```sh
./gradlew :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug
```

빌드 결과: `app/build/outputs/apk/debug/app-debug.apk`.

개인 검증용 APK는 표준 debug 서명입니다. Play 스토어 게시/제품용 서명·업데이트 채널은 구성하지 않았습니다. `specialUse` 포그라운드 서비스 사용 사유를 명시했으며, 스토어 게시 시 별도 정책 검토가 필요합니다.

## 자동 검증

테스트 장치를 지정해 아래를 실행합니다. **전용 에뮬레이터에서만** 실행하세요. 테스트가 에뮬레이터의 알림/알람/절전 예외 상태를 바꿉니다. 테스트 종료 시 강제 절전과 가상 배터리 상태는 복원합니다.

```sh
adb -s emulator-5554 install -r app/build/outputs/apk/debug/app-debug.apk
adb -s emulator-5554 install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s emulator-5554 shell am instrument -w kr.swim.phone.test/kr.swim.phone.EngineTestRunner
```

테스트 러너의 `assertions passed`와 각 PASS를 확인하세요. 이 자체 테스트 러너는 명령 실패 시에도 adb 프로세스 종료 코드는 0일 수 있으므로 출력 결과를 확인해야 합니다. 모든 예약 동작은 앱이 가로채 제공하는 모의 페이지에서만 수행합니다. 감시 재개 테스트에서는 모의 일정의 저장된 다음 시각만 앞당겨 만료를 재현하며, 실제 사이트 조회 간격을 줄이지 않습니다.

선택적 실제 사이트 **읽기 전용** 연결 확인(예약 폼 전송 없음):

```sh
adb -s emulator-5554 shell am instrument -w -e scenario live-inspect kr.swim.phone.test/kr.swim.phone.EngineTestRunner
```
