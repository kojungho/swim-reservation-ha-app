# 0.2.0-preview 검증 결과

검증일: 2026-10-25. 기존 HA 애드온은 소스·설정·배포·실행 모두 변경하지 않았다.

## 산출물

- 앱 ID `kr.swim.phone`, versionCode 4 / `0.2.0-preview`
- APK: `dist/swim-phone-0.2.0-preview.apk`
- SHA-256: `642c9d1b294e9a5acb1e40aeec0244691963f28ea11202fc4854abfd793fc156`
- `apksigner verify` 통과. 이전 0.1.x와 동일한 Android Debug 인증서.
- JDK 17 / Gradle 8.11.1 / AGP 8.10.1 빌드 성공.
- Lint 오류 0개, 경고 3개: 동기식 내구성 저장, 배터리 예외 요청 정책 검토, AGP 새 버전 안내. 경고를 숨기지 않았다.

## 화면 구성

- 애드온의 HTML·CSS를 APK의 로컬 화면으로 재사용했다. 달력 함수는 애드온 원본에서 가져와 변경 없이 사용하고 폰용 상태 어댑터만 연결했다.
- 같은 9개 메뉴, 날짜·시각 → 예약자 정보 → 객실 선택 → 저장 이력 순서, 설정·로그·기본 배치도·플로팅 맨 위로 기능을 제공한다.
- 입실일·박수 선택과 입실·퇴실 범위 선택을 설정에서 전환한다. 최대 6박, 선택 취소 시 미반영, 연도 변경, 시·분·초 선택을 검증했다.
- 예약자와 일정은 각각 최대 20개를 Keystore AES-GCM vault에 저장한다. 등록된 일정은 예약자 정보의 복사본이며 나중에 예약자를 삭제해도 영향을 받지 않는다. 동시에 실행하는 일정은 1개다.
- Android 시스템 상태 표시줄·내비게이션·키보드 영역을 제외한 컨테이너 안에서 로컬 화면을 표시해 고정 메뉴 겹침을 방지했다.

## 자동 검증

전용 읽기 전용 에뮬레이터(Android 17 / arm64 / 16KiB)에서 **최종 소스 68개 검증 항목 통과**.

핵심 추가 검증:

1. 9개 메뉴·14개 객실 체크 목록이 렌더링됨.
2. 선택한 객실과 우선순위가 실제 폰 일정 입력으로 전달되고 암호화 저장됨.
3. 애드온 달력이 지정한 월에 열리고 입실·퇴실 선택으로 박수를 계산함.
4. 날짜 선택 취소 시 기존 값 유지, 6박 초과 제한, 연도 경계 이동.
5. 실행 시각의 시·분·초 유지.
6. 설정에서 박수/퇴실일 방식 전환.
7. 미지원 다중 예약은 실행 화면을 제공하지 않음.
8. 취소 대기가 숨겨진 예약 실행 시각을 물려받지 않고, 1분 간격 입력을 거부함.
9. 로컬 UI origin만 허용하고 원격·파일 URL·스크립트 문서에는 UI 인터페이스를 노출하지 않음.
10. 예약자 삭제 이후에도 등록된 일정의 정보가 유지됨.
11. 새 예약자·일정 vault에 평문 개인정보가 없음.

기존 날짜/영수증 대조·중복 제출 마커·429 재제출 금지·Activity 종료 후 실행·강제 Doze·10분 감시 간격·조회 사이 CPU 잠금 해제·미래 시각의 조용한 대기·알람 기상·중지/재부팅 안전성 검증도 통과했다.

최종 예약 전송은 모두 앱이 가로채 제공하는 모의 페이지에서만 실행했다. 감시 재개는 모의 일정의 저장된 다음 시각을 만료시켜 검증했으며 실제 사이트의 10분 제한을 줄이지 않았다. 실기기 장시간 배터리/절전 검증은 별도로 필요하다.

## 시각 검증

최종 앱 화면·설정·달력 스크린샷을 확인했다. 상태 표시줄과 플로팅 메뉴의 겹침이 제거됐으며 달력과 범위 요약·취소 버튼이 화면 내에 표시됐다.

## 보안과 남은 제한

- 로컬 화면은 APK 내부 파일만 제공한다. HA 연결·UI 네트워크 폴링·DOM 저장소·파일 접근을 사용하지 않는다. 실제 예약 사이트를 여는 별도 엔진 WebView에는 JavaScript 인터페이스가 없다.
- 실행 요청에는 네이티브 확인 창과 기존 제출 잠금·권한 검사를 유지했다. UI에서 모의 플래그를 지정해 실제 실행 조건을 바꿀 수 없다.
- 다인·다중 실행, 앱 내 실제 예약 내역/월별 현황 수집, 사용자 지정 취소 감시 종료 시각, 서버 시간 동기화, 사진 갤러리·업데이터는 아직 미지원이다. 메뉴에서 미지원 안내 또는 공식 사이트 연결만 제공한다. 상단 시계는 ‘폰 시간’으로 구분했다.
- 지정 시각은 여전히 객실 조회부터 시작하는 시각이며 애드온의 서버 동기화 최종 제출 시각과 다르다.
- 사용자 폰과 개발 환경의 실제 사이트 HTTP 403은 해결되지 않았다. 이번 작업에서 실제 사이트 예약·취소 요청은 보내지 않았으며 실제 예약 성공을 검증하지 못했다.
