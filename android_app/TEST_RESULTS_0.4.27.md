# Android 0.4.27 (33) / addon 2.15.32 · 무통장 폼 호환성

## 원인과 동작

- 2026-11-01 00:00 일정은 시작·예약 폼·보안값·기간 검증을 통과했지만 두 예약자가 fieldsRecognized=true/bankRecognized=false로 최종 제출 전에 실패했습니다. 제출 마커는 모두 false였습니다. 이 로그의 실패 원인은 예약자명·전화번호나 0초 제출 간격/429가 아닙니다.
- 읽기 전용 공식 GET에서 현재 폼이 `input type=hidden name=pay_method value=bank`와 무통장입금 안내를 제공하는 것을 확인했습니다. 이전 엔진은 radio 입력만 인식했습니다. 원래 일정 기간의 시험 사이트는 현재 예약 불가 안내여서, 빈자리가 있는 다른 날짜의 공개 폼을 GET으로만 확인했습니다. 실제 예약·조회 개인정보 전송·취소·입금은 실행하지 않았습니다.
- 공통 DOM 함수는 고정 hidden bank, 기존 radio bank, 단일 select bank 옵션을 지원합니다. 카드 등이 기본이어도 bank만 선택하고, hidden은 수정하거나 변경 이벤트를 발생시키지 않습니다. 입력 후 및 최종 직전에는 성공적으로 전송될 pay_method가 정확히 하나의 bank인지 재확인합니다. 누락·비활성·중복·숨김/선택 혼합·카드 고정값·모호한 구조는 차단합니다. CSRF·기타 hidden 값·선택 동의를 임의로 수정하지 않습니다.
- Android와 애드온의 입력 함수 본문이 동일함을 자동 검사합니다. 애드온 assertForm과 Android 최종 제출 전 검사 모두 같은 읽기 전용 paymentOnly 경로를 재사용합니다. 결제 방식 검사 실패는 개인정보 입력 실패와 구분해 안내합니다.
- 제출 전이라는 명시적 증거가 있는 다인 실패는 예약 실패로 표시합니다. 제출 여부가 불명확한 오류는 계속 확인 필요이며, 모르는 결제 구조나 실패한 일정을 자동 재제출·재시작하지 않습니다.
