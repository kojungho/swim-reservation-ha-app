# Android 0.4.25 (31) · 배포 빌드 / 보안 점검

검증일: 2026-10-27. 실제 예약·취소·입금은 실행하지 않았습니다. HA 애드온과 운영 대기 일정은 변경하지 않았습니다.

## 확인된 문제 및 변경

- 이전 공개 0.4.24 APK는 `debuggable=true`인 debug 빌드였습니다. 0.4.25는 `assembleRelease`, `debuggable=false`, `jniDebuggable=false`입니다. 이는 배포 구성의 개선이며 Play Protect 경고의 직접 원인으로 확인된 것은 아닙니다.
- 기존 서명 키를 유지합니다. 키가 없거나 인증서 SHA-256이 다르면 release 서명 작업 자체를 거부합니다. 로컬 키 파일 권한은 소유자만 읽고 쓸 수 있도록 강화했습니다. 키 생성·교체·외부 업로드는 하지 않았습니다.
- 업데이트 메타데이터의 SHA-256이 선택 사항이었던 부분을 필수 검증으로 변경했습니다. 패키지·버전·서명 검증을 유지하고 debug/testOnly 업데이트 APK도 거부합니다.
- 새 APK 패키지 `kr.swim.phone`, 버전 0.4.25 / 31, 원래 서명 인증서 `027555e7a8662d3029c1c29112723855d40c490e17ea4410985d783ea78a3d19`, 단일 서명자, APK Signature Scheme v2 검증 성공.
- 기존 인증서 이름은 Android Debug입니다. 기존 앱의 업데이트 호환성 때문에 유지하며, Google Play용 키로 바뀐 것은 아닙니다. 기존 앱 삭제나 새 키로 교체하지 마세요.
- 검증 APK: `swim-phone-0.4.25.apk`, 2,358,900 bytes, SHA-256 `6806b6b5ad88c9a508c5100c387fd9732dd245892101c82b3996bce2cdbe71fb`.

## 코드 및 권한 점검

- SMS 읽기/수신, 접근성 서비스, 알림 수집 서비스, 연락처, 위치, 광범위 저장소 권한은 선언하지 않습니다.
- 설치 권한은 사용자가 요청한 자체 업데이트에 사용하고, 시스템 설치 확인을 자동 승인하지 않습니다. 비공개 캐시의 검증된 APK 하나만 읽기 전용 URI로 제공합니다.
- 알림·포그라운드 서비스·정확한 알람·부팅 복원·wake lock·배터리 최적화 예외는 사용자가 등록한 예약 대기/실행을 위한 기능입니다. 배터리 예외 권한은 민감한 검토 지점이며, 스토어 배포 시 정책 적합성 심사가 별도로 필요합니다. 숨겨진 SMS/접근성 권한으로 대체하지 않았습니다.
- 네이티브 Javascript 브리지는 앱에 동봉한 고정 로컬 화면에만 연결됩니다. 원격 예약/조회 WebView에는 브리지가 없습니다. 로컬 화면은 고정 파일 허용 목록과 CSP로 외부 문서·스크립트·폼·네트워크 요청을 차단합니다.
- 원격 예약/조회는 고정 HTTPS 호스트/주요 페이지를 검사하며 TLS 오류 시 중지합니다. 파일/콘텐츠 접근, 혼합 HTTP 콘텐츠, WebView 원격 디버깅은 비활성화됩니다. 사용자 확인 후 시작하는 예약 자동 입력은 앱 본래 기능이며 은폐하지 않았습니다.
- 공개 HA 설정 통신은 사진·표시 설정만 투영하며 인증 토큰/예약자/일정 데이터를 전송하지 않습니다. 리디렉션 거부, 크기 제한, 사진 해시·치수 검증을 유지합니다.
- 예약자·일정·초안 저장의 AES-GCM/Android Keystore 별칭, 저장소 이름, 패키지를 변경하지 않았습니다. 개인 데이터 백업은 비활성화 상태입니다.
- 원격 DEX 로더, 임의 명령 실행, TLS 검증 우회 코드는 이번 검색/검토 범위에서 발견하지 못했습니다. 이는 전체 공급망·모든 실행 경로에 대한 악성코드 무결성 인증은 아닙니다.

## 테스트

- JVM 자동 테스트 51개: 실패 0 (해시 필수/형식 및 다운로드 호스트·HTTPS 검증 2개 추가).
- release 빌드 및 lintRelease 성공: 오류 0, 경고 6. 기존 동기 SharedPreferences 저장 2, 배터리 예외 정책 검토 1, Gradle 업데이트 안내 1, 정적 객체 수명 검토 2. 경고를 숨기거나 전부 해결했다고 표시하지 않았습니다.
- 배포 검사 스크립트: 새 APK의 기존 인증서·패키지·버전·non-debug/non-test 통과. 이전 0.4.24 APK는 debuggable 사유로 거부되는 역검증 통과.
- Android 17/API 37 에뮬레이터에서 기존 0.4.24에 암호화한 시험 예약자·저장 일정·초안·설정을 저장한 뒤, 삭제 없이 0.4.25 release APK로 교체 설치 성공. 동일 정보를 복호화/비교하는 계측 테스트 성공. 시험 전 편집 정보 복원. 예약 엔진 시작 없음.
- non-debug release 앱에서 업데이트 라이프사이클·선택 업데이트·필수 호환성·잘못된 주소·진행 상태 보존 등 계측 검사 14개 통과. 모의 메타데이터만 사용했고 APK 설치 확인/실제 예약을 실행하지 않았습니다.

## Play Protect 경고: 아직 확인할 수 없는 부분

제공된 사진은 ‘잠재적으로 유해한 앱 / 피싱 시도 후 설치’ 표시입니다. Google 내부 판정 사유, 설치 유입 경로 판정, 기기 검사 로그가 없으므로 debug 빌드·자체 업데이트·예약 자동화 중 어느 것이 원인인지 단정할 수 없습니다. 실제 사용자 폰에서 새 APK의 정상 Play Protect 판정은 아직 확인하지 못했습니다. 경고가 계속되면 검사 기능을 끄거나 패키지/서명을 바꿔 우회하지 말고 Google에 검토를 요청해야 합니다. APK를 외부 분석 서비스에 제출하거나 이의 신청하지는 않았습니다.

공식 참고: [Play Protect 개발자 가이드](https://developers.google.com/android/play-protect/warning-dev-guidance), [Android 서명 안내](https://developer.android.com/studio/publish/app-signing).
