# Android 0.4.29 (35) · 주간 사전 점검 / 앱 문제점 로그

- 폰에 시작해 둔 미래 예약 대기 일정마다 별도 exact alarm을 등록합니다. 기본은 실행일 전날 10:00 KST, 지연 시 08~19시로 제한하며 실제 실행 5분 전에는 새 점검을 시작하지 않습니다. 두 분 시간 제한과 제한된 wake lock을 사용합니다. 앱 교체·재부팅·서버 시각 동기화·앱 재진입 시 알람을 복구합니다. 취소 감시·모의·이미 실행된 일정은 제외합니다.
- 열린 다른 달의 최대 7개 날짜에서 빈자리를 찾고 1박으로 각 예약자의 입력·무통장입금·필수 약관·기간·사이트를 검증합니다. GET-only native 다운로드와 네트워크가 차단된 오프라인 WebView를 사용합니다. 사이트 스크립트·이벤트 속성·외부 리소스는 실행하지 않습니다. 실제 제출 엔진과 같은 폼 입력·검증 함수를 쓰되 별도 읽기 검증 연산만 호출합니다. 최종 제출·예약 기록 생성·쿠키 초기화·실제 예약 상태 변경은 하지 않습니다. 사이트 JavaScript의 최종 접수 동작이나 실제 예약 성공을 보장하는 검사가 아닙니다.
- 점검 통과·오류·빈자리 없어 미완료를 앱 자체 알림과 실행 로그로 남깁니다. 별도 암호화 저널과 구성 해시로 중복을 방지하며 중지·수정 뒤 늦은 결과를 억제합니다. 재시작 당시 점검 중이었다면 중단 확인 필요로 알리고 자동 제출하지 않습니다. 기존 WAITING 상태·예약 알람·미확인 제출 마커와 독립적입니다.
- 사전 점검 문제 및 예약 실행 실패/확인 필요의 코드·단계·버전·시각·임의 익명 앱 구분값·중복 방지 ID만 HA로 보냅니다. 별도 암호화 대기열 최대 100개, 재연결/앱 재진입·프로세스 생존 중 재시도, 서버 ACK 일치 뒤에만 제거합니다. 이름·번호·실제 예약 ID·일정·원문 오류는 받거나 전송하지 않습니다. HA 애드온 2.15.35 및 공개 통합 1.0.2의 제한된 진단 POST가 필요합니다.
- Android JVM 63개 통과: 주간 계산, 알람/복구, 점검과 실제 대기 상태 분리, 중지/수정/중단/시간 제한, 암호화 대기열·ACK·무인증 최소 POST 및 기존 예약 실행/업데이트/개인정보 회귀. 빌드·lint 통과.
- Android 17/API37 WebView 모의 검사: 두 예약자 정상 입력, 사이트 스크립트·POST 시도 차단, 결제/전화 항목 변경 감지, 빈자리 없음, HTTP429에서 추가 재시도 없음. 합성 HTML/GET transport만 사용했고 예약·취소·입금은 추가로 실행하지 않았습니다. 예약 기록·에디터·실행 상태가 변하지 않음을 확인했습니다.
- 서버 폼/로그/공개 라우트 Node 검사 18개 및 HA Python 검사 9개 통과. HA 진단 경로는 GET/임의 경로/추가 개인정보/자유 문구를 거부하며 2KB·20건/분 제한, 이벤트 중복 억제를 적용합니다. 보고는 익명 미인증 앱 보고로 표시하고 기존 HA 인증을 우회하는 명령은 제공하지 않습니다.
