# 변경 기록

## 1.4.0

- 쉼오지 사이트에서 신규 객실명을 감지하면 체크 해제 상태로 우선순위 목록 끝에 자동 추가하고 영구 저장
- 2026년 9월 1일 실제 페이지에서 추가된 `온_산맥존`을 확인해 기본 객실 목록에도 반영
- 예약 완료 또는 확인 필요 상태가 되면 저장된 예약자 정보로 `예약확인`을 자동 실행
- `예약 정보 불러오기` 버튼 명칭을 `예약확인`으로 변경
- 예약 대기 중 객실 조회가 사전 준비 세션의 공유 Chromium을 닫아 `locator.evaluateAll` 오류를 일으키던 문제 수정
- 최근 1,000건의 실행 과정과 오류를 `/data`에 저장하고 조회·복사·텍스트 파일 저장이 가능한 실행 로그 영역 추가

## 1.3.1

- 저장 이력을 불러오면 복원된 숙박 날짜와 박수를 기준으로 객실 가능 여부도 즉시 다시 조회

## 1.3.0

- 예약자 정보를 최대 2개까지 서로 독립적으로 저장하고 `예약자 2명 사용`을 기본 OFF로 제공
- 예약자 1의 실제 완료 화면이 확인된 경우에만 예약자 2를 시작하는 엄격한 순차 처리 및 예약자별 상태 표시
- 우선순위 후보와 각 예약자 세션을 최종 제출 직전까지 순서대로 준비하고, 명확한 객실 마감 응답일 때만 다음 순위를 시도
- 후보 수와 예약자 수에 따라 사전 준비를 30초~5분 전에 시작하도록 조정
- 사전 준비 후보들은 Chromium 프로세스 하나의 독립 컨텍스트를 공유해 미니 PC 메모리 사용을 줄이고, 오픈 전 데이터가 없으면 실패 처리하지 않고 오픈 시 최신 페이지로 진행
- 예약 사이트 `Date` 헤더를 여러 번 측정해 가장 짧은 RTT 샘플로 서버 시각을 동기화하고, 스케줄러도 동기화 시각을 기준으로 실행
- 서버 시간·마지막 동기화·추정 시간 차이·RTT·동기화 상태 표시 및 5분 주기 재동기화
- 예약 오픈 전과 대기 중에도 서버가 제공한 객실 상태를 표시하고, 데이터 미제공 시 추정하지 않는 별도 상태 추가
- 모바일에서 Ingress 내부 리다이렉트가 외부 브라우저의 인증 쿠키를 잃어 401이 되던 문제를 제거하고, 인증된 API로 외부 예약 확인 URL을 받은 뒤 직접 이동
- `예약확인 사이트 이동` 문구와 주변 버튼 스타일 통일
- `설정 저장`을 4번 저장 이력으로, `사이트 위치 안내`를 2번 객실 우선순위로 이동

## 1.2.12

- `예약 가능 (예약 오픈 전)`은 노란색, `예약 불가 (예약 오픈 전)`은 빨간색 계열로 구분 표시

## 1.2.11

- 저장된 예약자 정보로 예약 확인 페이지를 읽어 객실·이용일·박수·금액·취소 가능 여부 표시
- 입금 전 취소 가능한 예약만 선택할 수 있고, 예약 세부 내용과 복구 불가 안내를 최종 확인한 뒤 취소
- 취소 요청 후 동일 예약이 목록에서 사라졌는지 다시 확인해 완료 여부 판정

## 1.2.10

- 저장된 예약자명과 휴대폰 번호로 사이트의 `예약 확인 및 취소` 페이지를 바로 여는 버튼 추가
- 한글 예약자명을 사이트 형식에 맞는 EUC-KR 주소로 안전하게 변환

## 1.2.9

- 예약 오픈 전에도 예약 페이지를 확인해 객실별로 `예약 가능 (예약 오픈 전)` 또는 `예약 불가 (예약 오픈 전)` 표시
- 선택한 숙박 날짜의 `예약 가능 시작 일시`를 날짜·시각 영역과 객실 확인 결과에 표시
