# 2.15.59 예약 화면 통합 및 카드 검토

- HA 예약 입력 메뉴를 다인 예약으로 통합. 한 행은 한 객실 예약, 같은 사람을 여러 행에 선택하면 다중 객실. 기존 단독/다중 일정은 보존하고 편집기로 불러올 때 후보/객실 행으로 변환.
- 기존 예약 입력에서 삼성카드 검토 선택 가능. 예약자·기간·인원·객실 후보를 서버에서 검증하고 공식 GET 금액을 확인한 뒤 후보별 검토를 명시적으로 시작. 후보를 모두 확정 주문으로 취급하지 않음.
- 카드 검토는 즉시 검토 전용. 기존 무통장입금 일정 실행과 분리하고 카드 선택 시 은행 예약 일정 등록/즉시 예약으로 흘러가지 않음. 예약 시각에 결제하는 기능은 아직 제공하지 않음.
- 현재 조건 준비는 5분 유효한 서버 메모리 식별자로 연결. 브라우저가 보낸 금액/객실 덮어쓰기는 불가. 동의 필수, 동일 후보 검토 자동 재시도 없음. 연결 검사에서 카드 복호화 없음.
- 카드 해제 암호는 UI에서 직접 입력, sessionStorage/로그/일정에 저장하지 않음. 기존 암호화 카드 유지. 최종 승인 버튼 비활성화 및 비밀번호 입력 전 전체 통신 차단 유지.
- 단독/다인/동일인 다중 객실 구성, 공식 금액 미확인 거부, 후보 대안 유지, 만료/동의/재시도 제한, 기존 일정 관리자, PC390/1280 화면: 관련 테스트 46개 통과.
- Chromium + Tesseract 완전 오프라인 샘플 테스트: 단독 1건, 다인 2건, 동일인 다중 2건 모두 세 입력값 검증·최종 승인 차단 통과. 외부 네트워크 없음.
- 기존 unified-workspace-ui의 예약자 새 입력 버튼 상태 검사는 변경 전 HEAD에서도 같은 실패 재현. 예약 조회 검사도 변경 전 HEAD에서 동일한 타임아웃 재현. 이 두 검사를 통과했다고 보고하지 않음.
- 이전 실제 HA 검사(2.15.58): 삼성 일반결제 이동 후 IPinside 설치 페이지로 전환되어 차단. HA에 필요한 보안 클라이언트 없음. 공식 Linux DEB는 3.0.0.15, 삼성 설정 요구는 3.0.0.19이며 인증서 신뢰 추가/상주 프로그램 설치가 필요하므로 설치하지 않음. 실카드 전체 자동입력/최종 결제 직전 도달 성공은 미확인.
