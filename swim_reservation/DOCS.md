# 쉼오지 예약 도우미

Home Assistant OS 미니 PC에서 예약 브라우저와 스케줄러를 계속 실행하고, Home Assistant Ingress 웹 화면으로 휴대폰과 컴퓨터에서 설정하는 App입니다.

## 사용 순서

1. App을 시작하고 **웹 UI 열기**를 누릅니다.
2. 숙박 시작 날짜를 선택합니다. `adaystart` 숫자와 예약 링크가 자동 생성됩니다.
3. 예약 실행 시각을 확인합니다. 기본값은 숙박월 두 달 전 1일 00:00:00입니다.
4. 객실을 체크하고 화살표로 우선순위를 정합니다.
5. 박수와 예약자 정보를 입력하고 **설정 저장**을 누릅니다.
6. **페이지 연결 확인**으로 미니 PC에서 대상 사이트에 접속할 수 있는지 확인합니다.
7. **예약 대기 시작**을 누릅니다.

이미 예약이 열린 날짜는 설정을 저장한 뒤 **지금 바로 예약**을 누르면 됩니다. 확인창에서 날짜, 박수, 객실 우선순위를 다시 확인하면 00시 대기 없이 즉시 최종 예약까지 진행합니다.

## 저장 이력

- 설정을 저장하면 `숙박 시작 날짜 + 박수` 조합으로 이력이 남습니다.
- 같은 날짜와 박수를 다시 저장하면 별도 중복을 만들지 않고 기존 이력을 최신 객실 순위와 예약자 정보로 갱신합니다.
- **불러오기**를 누르면 날짜, 실행 시각, 박수, 객실 우선순위와 예약자 정보 전체가 현재 설정으로 복원됩니다.
- **삭제**는 해당 저장 이력만 지우며 현재 화면에 불러온 설정은 유지합니다.
- 최근 50개 조합을 보관합니다.

App은 예약 30초 전에 Chromium을 열어 객실 선택, 첫 확인창, 환불 규정 동의, 두 번째 확인창과 저장된 예약자 정보 입력까지 준비합니다. 지정 시각(기본 00:00:00)에는 마지막 **예약하기**만 눌러 최종 제출합니다. 준비 단계와 최종 제출 직전에 `adaystart`를 다시 확인해 선택한 숙박 날짜가 유지된 경우에만 진행합니다.

예약 오픈 전에는 **지금 바로 예약**이 차단됩니다. 실행 중에는 각 페이지의 `adaystart`가 선택한 숙박 날짜와 같은지 확인하며, 사이트가 다른 날짜를 반환하면 최종 제출 전에 즉시 중지합니다.

최종 제출 후 사이트가 객실 마감이나 중복 예약을 명확히 안내하면 방금 시도한 객실을 제외하고 다음 우선순위 객실로 처음 단계부터 즉시 재진행합니다. 성공 여부를 판별할 수 없는 응답은 중복 예약을 방지하기 위해 재시도하지 않고 진단 정보와 함께 중지합니다.

예약 방식은 안전을 위해 분리되어 있습니다. **1개 예약 · 우선순위 방식**은 체크된 후보 중 하나만 성공할 때까지 순서대로 시도합니다. **여러 객실 동시 예약**은 체크한 객실(최대 5개) 모두를 실제 예약 대상으로 취급하며, 객실마다 독립된 PHP 세션에서 최종 제출 직전까지 준비한 뒤 지정 시각에 동시에 제출합니다. 동시 예약은 일부 객실만 성공할 수 있으므로 실행 상태에서 성공·실패 객실을 각각 확인해야 합니다.

숙박 시작 날짜와 박수를 바꾸면 객실 우선순위 옆에 **예약 가능**, **예약 완료**, **해당 박수 불가** 상태가 자동 표시됩니다. 아직 오픈되지 않은 숙박월은 사이트의 조기 표시를 신뢰하지 않고 **예약 오픈 전**으로 표시합니다. **사이트 위치 안내** 버튼을 누르면 하늘존·산맥존 배치도를 볼 수 있습니다.

## 데이터와 보안

- 객실 순위와 개인정보는 App의 `/data` 영역에 저장됩니다.
- 저장 이력에도 예약자 정보가 포함되므로 이력과 HA 백업 파일을 개인정보로 취급하세요.
- 이 데이터는 Home Assistant App 백업에 포함될 수 있으므로 백업 파일도 개인정보로 취급하세요.
- App은 Ingress 전용이며 외부 포트를 열지 않습니다.
- Home Assistant 자체의 원격 접속 보호를 사용하고 App 컨테이너 포트를 직접 인터넷에 노출하지 마세요.
- 대상 예약 사이트는 HTTP를 사용하므로 대상 사이트로 전송되는 개인정보는 HTTPS로 보호되지 않습니다.

## 제한 사항

- 대상 사이트의 화면 구조가 바뀌면 자동화 로직을 수정해야 할 수 있습니다.
- App은 선택한 예약 건별로 정상 예약 절차를 실행합니다. 단일 우선순위 모드의 재시도는 명확한 객실 마감일 때만 다음 후보로 진행하며 무한 반복하지 않습니다.
- 예약 성공은 사이트 응답과 동시 접속 경쟁 상황에 따라 보장할 수 없습니다.
- 예약 실행이 실패하면 실행 상태에 **실패 페이지 진단 정보**와 **진단 정보 복사** 버튼이 표시됩니다. 진단에는 URL, 폼, 필드의 `name`·`id`·`type`, 버튼, iframe 구조만 포함되며 입력값, 쿠키, 브라우저 저장소와 전체 HTML은 수집하지 않습니다.
- Mac Chrome에서는 **진단 정보 복사**를 누른 뒤 이 대화 입력창에서 `Command + V`로 붙여 넣으면 사이트 구조 변경 대응에 사용할 수 있습니다.
