# 쉼오지 예약 도우미

Home Assistant OS 미니 PC에서 예약 브라우저와 스케줄러를 계속 실행하고, Home Assistant Ingress 웹 화면으로 휴대폰과 컴퓨터에서 설정하는 App입니다.

## 사용 순서

1. App을 시작하고 **웹 UI 열기**를 누릅니다.
2. 숙박 시작 날짜를 선택합니다. `adaystart` 숫자와 예약 링크가 자동 생성됩니다.
3. 예약 실행 시각을 확인합니다. 기본값은 숙박월 두 달 전 1일 00:00:00입니다.
4. 객실을 체크하고 오른쪽 ⠿ 손잡이를 누른 채 원하는 위치로 드래그해 우선순위를 정합니다. PC·휴대폰 모두 지원하며, 키보드에서는 손잡이에 초점을 맞춘 뒤 위·아래 방향키를 사용할 수 있습니다. 변경 후 설정 저장을 누르세요.
5. 박수와 예약자 1 정보를 입력합니다. **+ 예약자 추가**로 최대 5명까지 등록할 수 있으며, 추가한 예약자는 개별 삭제할 수 있습니다. 설정 저장을 누르면 전체 예약자 정보가 저장됩니다. 여러 예약자는 우선순위 방식에서 순차 실행합니다.
6. 4번 **저장 이력** 영역에서 **설정 저장**을 누릅니다.
7. **페이지 연결 확인**으로 미니 PC에서 대상 사이트에 접속할 수 있는지 확인합니다.
8. **예약 대기 시작**을 누릅니다.

이미 예약이 열린 날짜는 설정을 저장한 뒤 **지금 바로 예약**을 누르면 됩니다. 확인창에서 날짜, 박수, 객실 우선순위를 다시 확인하면 00시 대기 없이 즉시 최종 예약까지 진행합니다.

## 저장 이력

- 설정을 저장하면 `숙박 시작 날짜 + 박수` 조합으로 이력이 남습니다.
- 같은 날짜와 박수를 다시 저장하면 별도 중복을 만들지 않고 기존 이력을 최신 객실 순위와 예약자 정보로 갱신합니다.
- **불러오기**를 누르면 날짜, 실행 시각, 박수, 객실 우선순위와 등록한 예약자 최대 5명의 정보가 모두 복원됩니다.
- **삭제**는 해당 저장 이력만 지우며 현재 화면에 불러온 설정은 유지합니다.
- 최근 50개 조합을 보관합니다.

App은 선택한 우선순위 수와 예약자 수에 따라 예약 30초~5분 전에 Chromium을 열어 각 후보의 객실 선택, 환불 규정 동의와 예약자 정보 입력까지 순서대로 준비합니다. 지정 시각(기본 00:00:00)에는 예약자 1의 후보를 순위대로 최종 제출합니다. 예약자 1의 실제 완료 화면을 확인한 뒤에만 예약자 2를 같은 방식으로 시작합니다. 준비 단계와 최종 제출 직전에 `adaystart`를 다시 확인해 선택한 숙박 날짜가 유지된 경우에만 진행합니다.

예약 오픈 전에는 **지금 바로 예약**이 차단됩니다. 실행 중에는 각 페이지의 `adaystart`가 선택한 숙박 날짜와 같은지 확인하며, 사이트가 다른 날짜를 반환하면 최종 제출 전에 즉시 중지합니다.

최종 제출 후 사이트가 객실 마감이나 중복 예약을 명확히 안내하면 다음 우선순위 후보를 즉시 제출합니다. 성공 여부를 판별할 수 없는 응답은 중복 예약을 방지하기 위해 재시도하지 않고 진단 정보와 함께 중지하며, 예약자 2도 시작하지 않습니다.

예약 방식은 안전을 위해 분리되어 있습니다. **1개 예약 · 우선순위 방식**은 체크된 후보 중 하나만 성공할 때까지 순서대로 시도합니다. **여러 객실 동시 예약**은 체크한 객실(최대 5개) 모두를 실제 예약 대상으로 취급하며, 객실마다 독립된 PHP 세션에서 최종 제출 직전까지 준비한 뒤 지정 시각에 동시에 제출합니다. 동시 예약은 일부 객실만 성공할 수 있으므로 실행 상태에서 성공·실패 객실을 각각 확인해야 합니다.

숙박 시작 날짜와 박수를 바꾸면 객실 우선순위 옆에 **예약 가능**, **예약 완료**, **해당 박수 불가** 상태가 자동 표시됩니다. 사이트에서 기존 목록에 없던 객실을 반환하면 체크 해제 상태로 목록 끝에 자동 추가하고 App 데이터에 저장합니다. 예약 오픈 전에도 서버가 제공한 결과는 **예약 가능 (예약 오픈 전)** 또는 **예약 불가 (예약 오픈 전)**로 구분합니다. 서버가 객실 데이터를 제공하지 않으면 임의로 추정하지 않고 **예약 오픈 전 - 서버에서 예약 가능 여부 미제공**으로 표시합니다. 2번 영역의 **사이트 위치 안내**를 누르면 하늘존·산맥존 배치도를 볼 수 있습니다.

## 서버 시간 동기화

- 예약 사이트 응답의 HTTP `Date` 헤더를 3회 측정하고 RTT가 가장 짧은 샘플을 사용합니다.
- 요청 왕복 구간의 중간값으로 시간 차이를 계산하고 monotonic clock으로 화면 시각과 예약 실행 판단을 이어갑니다.
- 5분마다 다시 동기화하며 화면에서 마지막 동기화, 시간 차이, RTT와 상태를 확인할 수 있습니다.
- 사이트가 제공하는 `Date` 값이 초 단위이므로 화면도 초 단위로 표시합니다. 예상 오차는 대략 서버 헤더의 1초 양자화 오차와 RTT 절반을 합친 범위입니다.
- 동기화에 실패하면 로컬 시간을 서버 시간으로 가장하지 않고 **서버 시간 동기화 실패**로 표시하며, 예약 대기·즉시 실행 전에 다시 동기화를 시도합니다.

## 예약 확인

**예약확인 사이트 이동**은 Ingress 안의 중간 주소를 외부 창에 여는 대신, 현재 인증된 Ingress 화면에서 외부 예약 확인 주소만 받아 그 사이트로 직접 이동합니다. 따라서 Home Assistant 앱 WebView나 모바일 외부 브라우저가 Ingress 인증 쿠키를 전달하지 못해 발생하던 401을 피하며, Ingress 토큰이나 경로를 하드코딩하지 않습니다.

실행 상태가 **예약 완료** 또는 **확인 필요**가 되면 App이 저장된 예약자 정보로 **예약확인**을 자동 실행하여 실제 예약 내역을 실행 상태 아래에 표시합니다. 수동으로 다시 확인하려면 **예약확인** 버튼을 누릅니다.

## 실행 로그

- 6번 **실행 로그** 영역에서 최근 실행 단계와 오류를 확인할 수 있습니다.
- 최근 1,000건을 App의 `/data/reservation-log.json`에 보관하므로 재시작 후에도 유지됩니다.
- **로그 복사**로 대화나 메모장에 붙여 넣을 수 있고 **로그 파일 저장**으로 UTF-8 텍스트 파일을 내려받을 수 있습니다.
- 예약자명·전화번호·생년월일 같은 입력값은 로그에 기록하지 않습니다. 기술 오류 원문, 진행 단계와 객실 결과만 기록합니다.

## 데이터와 보안

- 객실 순위와 개인정보는 App의 `/data` 영역에 저장됩니다.
- 저장 이력에도 예약자 정보가 포함되므로 이력과 HA 백업 파일을 개인정보로 취급하세요.
- 이 데이터는 Home Assistant App 백업에 포함될 수 있으므로 백업 파일도 개인정보로 취급하세요.
- App은 Ingress 전용이며 외부 포트를 열지 않습니다.
- Home Assistant 자체의 원격 접속 보호를 사용하고 App 컨테이너 포트를 직접 인터넷에 노출하지 마세요.
- 대상 예약 사이트는 HTTP를 사용하므로 대상 사이트로 전송되는 개인정보는 HTTPS로 보호되지 않습니다.

## 제한 사항

- 대상 사이트의 화면 구조가 바뀌면 자동화 로직을 수정해야 할 수 있습니다.
- App은 선택한 예약 건별로 정상 예약 절차를 실행합니다. 단일 우선순위 모드의 재시도는 명확한 객실 마감일 때만 다음 후보로 진행하며 무한 반복하지 않습니다.
- 예약 성공은 사이트 응답과 동시 접속 경쟁 상황에 따라 보장할 수 없습니다.
- 예약 실행이 실패하면 실행 상태에 **실패 페이지 진단 정보**와 **진단 정보 복사** 버튼이 표시됩니다. 진단에는 URL, 폼, 필드의 `name`·`id`·`type`, 버튼, iframe 구조만 포함되며 입력값, 쿠키, 브라우저 저장소와 전체 HTML은 수집하지 않습니다.
- Mac Chrome에서는 **진단 정보 복사**를 누른 뒤 이 대화 입력창에서 `Command + V`로 붙여 넣으면 사이트 구조 변경 대응에 사용할 수 있습니다.
# 사이트 위치 안내 사진 변경

객실 우선순위 옆 **사이트 위치 안내**를 열고 **사진 선택·등록**을 누르세요. PC 파일이나 휴대폰 사진을 선택하면 자동 등록됩니다. 등록한 사진은 모든 기기에서 공유되며 앱 재시작·업데이트 후에도 유지됩니다.

30MB 이하의 사진을 선택하세요. 브라우저에서 읽을 수 있는 사진을 자동 축소해 저장합니다. HEIC 등 형식을 읽지 못한다는 안내가 나오면 JPG 또는 PNG로 저장한 사진을 선택하세요.
# 예약자 저장·조회 및 예약자별 동시 예약 (1.6.0)

예약자 정보 영역의 **예약자 정보 저장**은 숙박 날짜·박수·객실 선택과 관계없이 최대 5명의 정보를 `/data/reservation-profiles.json`에 저장합니다. 업데이트·재시작 후에도 유지되고, 저장 이력을 불러와도 별도 저장된 예약자 목록을 덮어쓰지 않습니다. **저장된 예약자 불러오기**로 현재 입력란에 다시 채울 수 있습니다. 전체 **설정 저장**을 할 때도 예약자 목록을 갱신합니다.

**예약확인** 버튼은 현재 입력한 모든 예약자를 별도로 저장한 뒤 모두 조회합니다. 자동 예약확인은 별도 저장된 목록을 사용합니다. 조회에 실패한 사람은 0건으로 표시하지 않고 오류를 표시하며, 나머지 사람의 조회 결과는 보존합니다. 조회 결과에는 예약자별 건수가 표시됩니다. 예약 대기·실행 중에는 조회와 예약자 저장을 사용할 수 없습니다.

**사이트 이동할 예약자**를 고르고 **예약확인 사이트 이동**을 누르면 선택한 한 명의 현재 예약자명·전화번호만 사용해 사이트를 엽니다. 다른 사람의 입력이 미완성이어도 해당 한 명의 정보가 유효하면 이동할 수 있습니다.

- **1개 예약 · 우선순위 방식**: 공통 객실 순위를 사용해 예약자를 순차 진행합니다. 앞 예약자 실패·불확실 시 이후 예약자 중단.
- **여러 객실 동시 예약**: 저장된 예약자가 여러 명이어도 선택할 수 있습니다. 예약자 정보 영역의 **여러 객실을 예약할 예약자**에서 한 명을 선택하면 그 사람의 정보로 체크한 객실을 각각 예약합니다. 다른 예약자 정보는 유지되지만 이 모드에서는 실행하지 않습니다. 체크한 객실 모두가 예약 대상이므로 순위별 대체 예약이 아닙니다.
- **예약자별 동시 예약 · 우선순위**: 최대 5명의 개인별 순위를 입력하고 한 사람당 객실 하나를 예약합니다. 개인 순위는 이 모드에서만 사용합니다. 각 예약자는 독립 세션으로 함께 시작하며, 확실한 마감만 자기 다음 순위로 이동합니다. 불확실한 결과는 해당 예약자의 추가 제출을 중단하고 다른 예약자의 이미 시작된 실행은 독립적으로 진행됩니다.

동시 모드는 사이트가 허용하면 지정 시각 전에 정보 입력까지 마친 뒤 최종 제출을 진행합니다. 오픈 전 페이지에 객실 정보가 없거나 다음 단계 접근이 제한되면 그 예약자는 지정 시각에 처음부터 진행합니다. 서버 시간 동기화, 브라우저 처리·네트워크 지연 때문에 모든 요청의 서버 도착이나 예약 완료가 같은 밀리초일 수는 없습니다. 여러 사람의 순위에 같은 객실을 넣으면 서로 경쟁할 수 있으므로 다른 1순위를 권장합니다. 실제 예약·취소는 사용자 확인 후에만 실행하세요.
# 월별 전체 예약 현황 (1.7.3)

상단 **쉼오지 예약 도우미** 제목 옆의 **월별 예약 현황** 버튼을 누르면 숙박 시작 날짜의 달을 기본으로 조회합니다. 조회할 월을 직접 지정하고 **조회**를 누르거나 이전·다음 달 버튼을 이용할 수 있습니다. 날짜를 누르면 숙박 시작 날짜·링크·예약 오픈 시각에 반영하고 달력을 닫아 예약 매크로 화면의 날짜 입력 위치로 이동합니다. 예약자 정보·객실 우선순위는 유지되며, 날짜 선택만으로 저장이나 예약이 실행되지는 않습니다.

요일별 달력은 날짜마다 객실 목록을 표시합니다. 이름은 구역명을 빼고 해·샘·숲처럼 짧게 표시하며, 각 이름 옆에 초록 **가**(예약 가능), 빨강 **완**(예약 완료), 파랑 **대**(예약 대기), 갈색 **불**(1박 불가), 회색 **?**(확인 불가)를 붙입니다. 전체 이름과 상태는 각 객실 행의 도움말로 유지합니다. 표시 상태는 조회 시점의 정보이며, 실제 예약 성공이나 여러 박의 연속 예약 가능 여부를 보장하지 않습니다.

월별 페이지에 데이터가 없는 날짜는 `reservation1.php`의 개별 날짜 링크를 순차 조회합니다. 달력이 열려 있을 때만 조회하며 확인된 날짜부터 표시합니다. 개별 페이지에서도 확인할 수 없으면 **조회 실패 / 확인 불가**로 구분하고 가능·완료로 추정하지 않습니다. 사이트의 숙박 날짜를 검증해 다른 날짜의 객실 현황은 반영하지 않습니다. 예약 오픈 일시는 기존 숙박월 두 달 전 1일 00시 규칙으로 함께 표시합니다.

자동 예약 사전 준비·실행 중에는 월별 조회를 제한하며, 일반 객실 조회와 같은 독립 대기열을 사용해 예약 브라우저와 충돌하지 않습니다. 조회 창을 닫으면 진행 중인 조회를 취소합니다. 실패 시 이전 달 결과를 최신 결과로 재사용하지 않습니다. **원본 월별 현황 사이트** 링크로 원본과 비교할 수 있습니다.
