# 쉼오지 예약 도우미 2.15.2

## 단계별 진단 로그

실행 기록에서 예약 시도 ID(`attemptId`), 일정 ID(`planId`), 예약자 순번, 사이트, 단계(`step`), 시작·완료·실패(`outcome`), 소요시간, HTTP 상태를 확인할 수 있습니다. 상세 조회는 `detailIndex`로 구분합니다. 취소 대기의 조회 로그와 브라우저 조회는 동일 시도 ID로 연결됩니다.

예약 폼·보안값·사이트·기간·인원, 필수 약관·무통장·입력 검증과 완료 화면 대조는 `checks`의 참/거짓으로 어떤 검사가 실패했는지 기록합니다. 입력·약관은 한 번에 실행하고 내부 단계 결과만 모아서 남깁니다(`single-browser-batch`). 입력 실패 항목은 `invalidFields`, 실패 내부 단계는 `substep`, 시간초과·네트워크·페이지 종료 등은 `failureKind`로 구분합니다. 예약 조회의 목록·개별 상세 및 월별 달력도 별도 단계로 추적합니다.

새 진단 로그의 예약자 식별 정보는 `가*다`, `010-****-5678`처럼 가운데를 가립니다. 입력 원문·생년월일·요청사항·토큰·응답 본문은 새 진단 정보에 포함하지 않습니다. 기존에 저장된 로그와 사용자가 정한 일정 이름을 소급 수정하지 않으므로 공유 전 확인하세요. 로그는 최근 1,000개로 순환 보관되므로 오류가 나면 실행 기록을 내려받아 보관하세요. 로그만으로 사이트 내부 차단 규칙이나 실제 예약 여부를 확정할 수는 없으며 결과 불명확 시 공식 예약 조회로 확인해야 합니다.

## 휴대폰 오류 알림

예약 실행 실패·부분 실패·결과 확인 필요 및 취소 대기 조회 오류를 HA 모바일 앱으로 알립니다. 기본 대상은 S25 `notify.mobile_app_sm_s938n`이며 애드온 구성의 `error_notify_service`에서 서비스 이름(`notify.` 제외)을 변경할 수 있습니다. 빈 문자열은 발송을 끕니다. HA Core 연결 및 휴대폰 HA 앱의 알림 권한이 필요합니다.

동일 일정의 같은 종류 오류는 5분 동안 중복 발송하지 않습니다. 새 실행을 시작하면 다시 알립니다. 알림에는 예약자 정보·연락처·원문 오류를 포함하지 않습니다. 알림을 누르면 애드온으로 이동하며, 상세 오류와 실제 예약 여부는 실행 기록·예약 조회로 확인하세요. 일반 수동 조회 오류나 정상 대기·빈자리 없음은 오류 알림 대상이 아닙니다. HA 서비스가 요청을 수락해도 휴대폰 오프라인·방해 금지·알림 차단 등에 따라 표시가 늦거나 안 될 수 있습니다.

Home Assistant OS에서 예약 엔진을 실행하고 Ingress 화면으로 설정합니다. 새 공식 사이트는 https://www.swimozicamp.com/camp/ 입니다. 안드로이드 앱과 브라우저 확장 프로그램은 이번 배포에 포함하지 않습니다.

## 업데이트 후 확인

- 이전 사이트의 저장된 예약자와 설정은 보존합니다. 생년월일은 새 사이트에서 사용하지 않습니다.
- 이전 사이트에서 등록한 대기 일정은 자동 재개하지 않습니다. 사이트·날짜·예약자를 확인하고 수정 저장한 뒤 시작하세요.
- 서버와 화면 버전이 다르면 화면 새로 열기 안내가 표시됩니다. 편집 중인 내용을 확인한 뒤 화면을 새로고침하세요.
- 기존 월별 객실 상태 캐시는 새 사이트에서 재사용하지 않습니다.

## 예약 설정과 실행

1. 입실일과 박수를 선택합니다. 기본 실행 시각은 숙박월 두 달 전 1일 00시입니다. 실제 공식 사이트의 오픈 안내를 우선 확인하세요.
2. 저장된 예약자를 선택하거나 이름과 휴대폰 번호를 입력합니다. 연락처는 숫자로 전송합니다.
3. 입금자명은 선택 입력이며 비워두면 예약자명을 사용합니다. 성인 인원(1~2명), 도착 예정 시간과 요청사항도 확인하세요.
4. 객실을 체크하고 단독·다인 예약에서는 우선순위를 정합니다. 오픈 전 후보 선택은 빈자리 보장이 아닙니다.
5. 일정 이름을 입력하고 등록합니다. 등록만으로 실행하지 않습니다. 목록에서 시작을 누르면 대기 또는 취소 자리 감시를 시작합니다.
6. 오픈된 날짜는 확인창을 거쳐 지금 바로 예약을 실행할 수 있습니다. 등록한 일정은 이후 편집과 독립적으로 유지됩니다.

실행 시각에 선택한 사이트의 예약정보 입력 페이지로 직접 들어갑니다. 날짜·사이트·인원·보안 입력값을 검증한 후 예약자 정보와 필수 약관을 한 번에 입력·체크합니다. 입력이 끝나면 최종 예약 신청을 제출하고 완료 화면의 예약번호·예약자·사이트·기간·금액·상태를 대조합니다. 오픈 전에 미리 정보를 입력하지 않습니다.

오픈 직후 예약 화면이 늦게 제공되면 짧은 준비 구간에서 2초 간격으로 최대 3회 GET 조회만 재확인합니다. HTTP 오류나 알 수 없는 화면은 무조건 재시도하지 않습니다. 최종 제출 후 결과가 불확실하면 다른 객실에 다시 제출하지 않습니다.

자동 예약은 **무통장입금 신청까지**입니다. 신청 완료는 입금 대기이며 예약 확정이나 입금 완료가 아닙니다. 안내된 기한 안에 직접 입금하세요. 카드·계좌이체 자동 결제와 온라인 예약 취소는 지원하지 않습니다. 취소는 공식 사이트 안내에 따라 캠핑장에 문의하세요.

## 단독·다중·다인·취소 대기

- 단독: 선택한 한 명으로 우선순위 중 객실 하나를 예약합니다.
- 다중: 선택한 한 명으로 체크한 객실(최대 5개)을 각각 예약합니다.
- 다인: 각 예약자가 자기 우선순위로 객실 하나를 예약합니다. 사람별 독립 브라우저 세션에서 준비합니다. 같은 1순위는 서로 경쟁할 수 있습니다.
- 취소 대기: 지정 날짜·박수의 공개 빈자리 목록을 조회하고 체크한 사이트가 나타나면 예약을 시도합니다. 종료일과 조회 간격을 확인하세요. 예약 실행 중 다른 조회는 양보합니다.

**설정 → 예약 제출 간격**은 다인·다중의 최종 제출 시작 사이 간격입니다. 기본 5초이며 0~60초로 저장합니다. 0초는 인위적인 지연과 순차 제출을 없앱니다. 각 화면의 준비 속도에 따라 실제 제출 시각은 달라질 수 있습니다. 설정은 다음 실행부터 적용합니다.

429는 사이트의 요청 제한입니다. 429 확인 뒤 아직 보내지 않은 새 제출과 자동 재제출을 중단합니다. 0초에서는 여러 요청이 이미 나간 뒤 429를 받을 수 있으며, 이미 전송된 요청은 회수할 수 없습니다. 반드시 예약 조회로 결과를 확인하세요. 새 사이트의 실제 다인 0초 제출에서 429가 발생하는지는 별도 사용자 테스트가 필요합니다.

## 예약 조회

예약 조회 탭에서 저장한 조회용 이름·휴대폰 번호로 조회하거나 1회성 조회를 사용합니다. 예약정보 관리와 조회용 목록은 독립적입니다. 공식 사이트 열기 링크에 이름·전화번호를 넣지 않습니다.

다건 목록은 사이트가 제공한 자세히 보기 폼으로 각 상세를 1초 간격으로 순차 조회합니다. 공개 번호가 없는 요약 항목도 원본 선택값만 사용합니다. 상세의 예약자·예약번호·객실·숙박일·박수·인원·금액·상태를 확인합니다. 입금 대기와 예약 확정을 구분하고 입금 기한을 표시합니다.

알 수 없는 목록이나 일부 상세 조회 실패는 정상 0건으로 표시하지 않습니다. 403·429 및 상세 오류에서는 자동 재조회하지 않습니다. 개인 조회 토큰·보안 입력값·계좌 원문은 조회 결과나 로그로 반환하지 않습니다.

## 빈자리와 월별 현황

선택 날짜와 박수의 빈자리 목록에는 예약 가능한 사이트만 나옵니다. 목록에 없다고 모두 예약 완료나 입금 대기로 추정하지 않습니다. 기존 1~14번 외의 새 사이트가 공개 빈자리 목록에 나타나면 비선택 후보로 추가하고 보존합니다. 새 사이트가 한 번도 목록에 나타나지 않았다면 자동 발견되지 않을 수 있습니다.

월별 달력은 날짜별 남은 사이트 수만 제공합니다. 개별 객실의 예약 상태나 연속 박수 예약 가능 여부를 보장하지 않습니다. 오픈 전 수치를 예약 가능으로 표시하지 않습니다.

이번 달에서 3개월 뒤 달의 잔여 수를 기본 1시간 간격으로 미리 조회합니다. 월별 화면에서 자동 조회를 끄거나 간격을 바꿀 수 있습니다. 예약 실행과 실행 시각 직전에는 조회를 양보합니다. API 실패 뒤 전체 날짜별 조회를 연달아 실행하지 않습니다.

## 저장·화면·개인정보

예약자는 최대 20명, 일정은 최대 20개, 활성 일정은 최대 5개입니다. 일정 등록·탭 이동 때 입력을 초기화해도 저장 목록과 기존 일정은 유지됩니다. 완료·실행 결과가 불확실한 일정은 예약 조회로 확인한 뒤 새로 등록하세요.

설정에서 글자 크기·표시 여부·플로팅 위치·아이콘·크기를 저장합니다. 스크롤하면 맨 위로 버튼이 표시됩니다. 배치도와 안내 사진은 참고용이며 공식 사이트의 최신 배치를 확인하세요.

개인정보와 예약 설정은 HA 애드온 데이터 폴더에 보관됩니다. 백업에도 포함될 수 있으니 안전하게 관리하세요. 로그를 공유할 때 일정 이름 등 사용자 지정 정보가 포함되는지 먼저 확인하세요.

새 공식 사이트는 HTTPS를 사용합니다. 애드온 포트를 인터넷에 직접 공개하지 말고 Home Assistant Ingress를 사용하세요. 네트워크·사이트 제한·경쟁 상황에 따라 예약 성공을 보장하지 않습니다.
