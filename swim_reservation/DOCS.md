# 쉼오지 예약 도우미

Home Assistant OS 미니 PC에서 예약 브라우저와 스케줄러를 계속 실행하고, Home Assistant Ingress 웹 화면으로 휴대폰과 컴퓨터에서 설정하는 App입니다.

## 사용 순서

1. App을 시작하고 **웹 UI 열기**를 누릅니다.
2. 숙박 시작 날짜를 선택합니다. `adaystart` 숫자와 예약 링크가 자동 생성됩니다.
3. 예약 실행 시각을 확인합니다. 기본값은 숙박월 두 달 전 1일 00:00:00입니다.
4. **예약자 정보** 탭에서 예약용 정보를 최대 5명 저장하세요. 모든 예약 모드에 목록이 자동 표시됩니다. **예약에 사용할 정보**에서 한 명을 선택하거나 직접 입력합니다. 예약자별 동시만 **+ 예약자 추가**로 필요한 사람을 최대 5명 선택·입력할 수 있습니다. 저장된 사람 수만큼 입력란을 자동 생성하지는 않습니다.
5. 아래에서 객실을 체크합니다. 1개 예약·예약자별 동시는 손잡이로 순위를 정하고, 여러 객실 동시·취소 자리 감시는 체크만 합니다. PC·폰 드래그와 키보드 위·아래 이동을 지원합니다.
6. 모드 안에서 새로운 사람을 직접 입력하면 **예약자 저장**으로 선택 목록에 추가할 수 있습니다. **설정 저장**은 일정 설정만 저장하며 예약자 목록을 덮어쓰지 않습니다. 이름·휴대폰 번호만 보관하는 **예약 조회** 탭의 저장과는 별개입니다.
7. 객실 영역의 **새로 고침**은 연결과 날짜·박수 조건을 다시 확인하는 선택 기능입니다. 결과는 객실 목록의 상태 표시로만 확인하며, 중복된 별도 객실 확인 결과 목록은 표시하지 않습니다. 조회 오류 안내는 유지합니다.
8. **예약 실행** 바로 아래 **여러 일정 진행**에서 일정 이름을 넣고 **예약 일정 등록**을 누른 뒤 목록의 **시작**을 누릅니다. 미래 시각 예약과 취소 자리 감시는 모두 등록 후 시작합니다.

이미 예약이 열린 날짜이고 입력한 실행 시각이 사이트 서버 시간 기준으로 지났다면 **지금 바로 예약**을 사용할 수 있습니다. 미래 실행 시각, 취소 자리 감시, 서버 시간 미확인 상태에서는 표시하지 않습니다. 확인창에서 날짜·박수·객실 조건을 다시 확인하면 현재 설정을 저장하고 즉시 최종 예약까지 진행합니다.

## 저장 이력

- 설정을 저장하면 `숙박 시작 날짜 + 박수` 조합으로 이력이 남습니다.
- 같은 날짜와 박수를 다시 저장하면 별도 중복을 만들지 않고 기존 이력을 최신 객실 순위와 예약자 정보로 갱신합니다.
- **불러오기**를 누르면 날짜, 실행 시각, 박수, 객실 우선순위와 등록한 예약자 최대 5명의 정보가 모두 복원됩니다.
- **삭제**는 해당 저장 이력만 지우며 현재 화면에 불러온 설정은 유지합니다.
- 최근 50개 조합을 보관합니다.

App은 후보 수와 사람 수에 따라 예약 30초~5분 전에 객실 선택, 환불 규정 동의와 정보 입력까지 미리 준비합니다. 1개 예약은 한 사람의 후보를 순위대로, 여러 객실 동시는 체크한 객실들을 같은 사람으로, 예약자별 동시는 각 사람의 후보들을 함께 최종 제출합니다. 준비 단계와 최종 제출 직전에 `adaystart`를 다시 확인합니다.

예약 오픈 전에는 **지금 바로 예약**이 차단됩니다. 실행 중에는 각 페이지의 `adaystart`가 선택한 숙박 날짜와 같은지 확인하며, 사이트가 다른 날짜를 반환하면 최종 제출 전에 즉시 중지합니다.

최종 제출 후 사이트가 객실 마감이나 중복 예약을 명확히 안내하면 우선순위 모드에서는 다음 후보를 시도합니다. 성공 여부를 판별할 수 없는 응답은 해당 예약자의 중복 예약을 방지하기 위해 재제출하지 않고 중지합니다.

예약 방식은 안전을 위해 분리되어 있습니다. **1개 예약 · 우선순위 방식**은 체크된 후보 중 하나만 성공할 때까지 순서대로 시도합니다. **여러 객실 동시 예약**은 체크한 객실(최대 5개) 모두를 실제 예약 대상으로 취급하며, 객실마다 독립된 PHP 세션에서 최종 제출 직전까지 준비한 뒤 지정 시각에 동시에 제출합니다. 동시 예약은 일부 객실만 성공할 수 있으므로 실행 상태에서 성공·실패 객실을 각각 확인해야 합니다.

숙박 시작 날짜와 박수를 바꾸면 객실 목록에 **예약 가능**, **예약 완료**, **해당 박수 불가** 상태가 자동 표시됩니다. 사이트에서 기존 목록에 없던 객실을 반환하면 체크 해제 상태로 목록 끝에 자동 추가하고 App 데이터에 저장합니다. 예약 오픈 전에도 서버가 제공한 결과는 **예약 가능 (예약 오픈 전)** 또는 **예약 불가 (예약 오픈 전)**로 구분합니다. 서버가 객실 데이터를 제공하지 않으면 임의로 추정하지 않고 **예약 오픈 전 - 서버에서 예약 가능 여부 미제공**으로 표시합니다. 오른쪽 아래 플로팅 **사이트 위치** 버튼으로 배치도를 볼 수 있습니다. 모바일은 지도 이모티콘으로 표시되며 모든 탭에서 스크롤해도 유지됩니다. 객실 목록에는 구역명을 유지하고 다른 화면에서는 이름만 표시합니다. 사이트 요청·저장 데이터·복사 및 내려받는 진단/로그 원본은 유지됩니다.

## 서버 시간 동기화

- 예약 사이트 응답의 HTTP `Date` 헤더를 3회 측정하고 RTT가 가장 짧은 샘플을 사용합니다.
- 요청 왕복 구간의 중간값으로 시간 차이를 계산하고 monotonic clock으로 화면 시각과 예약 실행 판단을 이어갑니다.
- 5분마다 다시 동기화하며 화면에서 마지막 동기화, 시간 차이, RTT와 상태를 확인할 수 있습니다.
- 사이트가 제공하는 `Date` 값이 초 단위이므로 화면도 초 단위로 표시합니다. 예상 오차는 대략 서버 헤더의 1초 양자화 오차와 RTT 절반을 합친 범위입니다.
- 동기화에 실패하면 로컬 시간을 서버 시간으로 가장하지 않고 **서버 시간 동기화 실패**로 표시하며, 예약 대기·즉시 실행 전에 다시 동기화를 시도합니다.

## 예약 확인

**예약 조회** 탭에는 최대 5명의 예약자명·휴대폰 번호만 저장합니다. 입금자명·생년월일·객실 조건은 저장하지 않습니다. **저장·조회**로 저장하고 조회하며, 페이지 진입 시에는 이미 저장된 대상을 조회합니다. **사이트 조회**는 선택한 조회용 이름·번호로 원본 사이트를 직접 엽니다. Ingress 토큰·경로를 외부에 전달하지 않습니다. 이름·전화번호는 나란히 표시되고 **삭제**는 대상 카드 제목 옆에 있습니다. PC에서는 대상 카드도 2열로 배치합니다.

조회용 정보는 `/data/reservation-lookup-profiles.json`에 예약용 파일과 분리됩니다. 최초 업데이트 때 기존 예약용 이름·전화번호만 한 번 복사하며 이후 예약 설정 저장으로 덮어쓰지 않습니다. 조회용 저장은 예약용 정보·진행 중인 일정을 변경하지 않습니다. 예약 조회·취소는 조회용 대상을 사용하므로 다른 이름으로 실제 예약했다면 그 이름·번호를 조회 대상으로 저장하세요.

## 실행 로그

- **실행 로그** 탭에서 최근 실행 단계·오류·진단 정보를 확인할 수 있습니다. 탭 진입 시 로그를 다시 조회합니다.
- 최근 1,000건을 App의 `/data/reservation-log.json`에 보관하므로 재시작 후에도 유지됩니다.
- 실행 로그 탭의 **복사**로 대화나 메모장에 붙여 넣을 수 있고 **파일 저장**으로 UTF-8 텍스트 파일을 내려받을 수 있습니다.
- 입력 전화번호·생년월일을 직접 기록하지 않지만 사용자가 지정한 일정 이름, 조회 대상 이름, 기술 오류 문구가 포함될 수 있으므로 공유 전에 확인하세요.

## 데이터와 보안

- 객실 순위와 개인정보는 App의 `/data` 영역에 저장됩니다.
- 저장 이력에도 예약자 정보가 포함되므로 이력과 HA 백업 파일을 개인정보로 취급하세요.
- 이 데이터는 Home Assistant App 백업에 포함될 수 있으므로 백업 파일도 개인정보로 취급하세요.
- App은 Ingress 전용이며 외부 포트를 열지 않습니다.
- Home Assistant 자체의 원격 접속 보호를 사용하고 App 컨테이너 포트를 직접 인터넷에 노출하지 마세요.
- 대상 예약 사이트는 HTTP를 사용하므로 대상 사이트로 전송되는 개인정보는 HTTPS로 보호되지 않습니다.

## 제한 사항

- 대상 사이트의 화면 구조가 바뀌면 자동화 로직을 수정해야 할 수 있습니다.
- App은 선택한 예약 건별로 정상 예약 절차를 실행합니다. 단일 우선순위 모드의 재시도는 명확한 객실 마감일 때만 다음 후보로 진행하며 무한 반복하지 않습니다.
- 예약 성공은 사이트 응답과 동시 접속 경쟁 상황에 따라 보장할 수 없습니다.
- 예약 실행이 실패하면 실행 상태에 **실패 페이지 진단 정보**와 **진단 정보 복사** 버튼이 표시됩니다. 진단에는 URL, 폼, 필드의 `name`·`id`·`type`, 버튼, iframe 구조만 포함되며 입력값, 쿠키, 브라우저 저장소와 전체 HTML은 수집하지 않습니다.
- Mac Chrome에서는 **진단 정보 복사**를 누른 뒤 이 대화 입력창에서 `Command + V`로 붙여 넣으면 사이트 구조 변경 대응에 사용할 수 있습니다.
# 사이트 위치 안내 사진 변경

오른쪽 아래 **사이트 위치**(모바일 🗺️)를 열고 **사진 선택·등록**을 누르세요. PC 파일이나 휴대폰 사진을 선택하면 자동 등록됩니다. 등록한 사진은 모든 기기에서 공유되며 앱 재시작·업데이트 후에도 유지됩니다.

30MB 이하의 사진을 선택하세요. 브라우저에서 읽을 수 있는 사진을 자동 축소해 저장합니다. HEIC 등 형식을 읽지 못한다는 안내가 나오면 JPG 또는 PNG로 저장한 사진을 선택하세요.
# 예약용 정보와 조회용 정보 (2.2.0)

상단 **쉼오지 예약 도우미** 제목 옆 **ⓘ**를 누르면 예약 모드별 사용 방법을 볼 수 있습니다. 모든 탭에서 열 수 있으며, 취소 자리 감시에서는 감시 안내를 펼칩니다.

**예약자 정보** 탭에서 이름·입금자명·전화번호·생년월일을 최대 5명 추가·삭제하며 `/data/reservation-profiles.json`에 보관합니다. 모든 모드에는 **저장된 예약자 선택** 목록이 자동 표시됩니다. 선택하기 전에는 입력란이 비어 있고, 저장된 사람 수와 무관하게 예약자별 동시도 한 명의 빈 입력란으로 시작합니다. 필요한 사람만 **+ 예약자 추가**로 늘려 각각 선택하세요. 새로 직접 입력한 사람이 저장 목록에 없다면 **예약자 저장** 버튼이 활성화되어 목록에 추가할 수 있습니다. 같은 사람은 중복 저장하지 않으며, 5명이 가득 찼으면 전용 탭에서 삭제 후 추가하세요.

입력 중인 사람을 **이 일정에서 제외**하는 것은 저장 목록 삭제와 다릅니다. 일정 등록·탭 이동 시 사람 선택과 미등록 입력을 초기화하지만 저장 목록과 이미 등록한 일정은 유지합니다. **설정 저장**은 예약자 관리 목록을 덮어쓰지 않습니다. 저장된 사람을 모두 삭제해도 빈 목록이 유지됩니다. 예약자별 동시 이외의 모드에는 한 명의 입력란과 실제 예약자만 포함됩니다.

**예약 조회** 탭은 이름·전화번호만 별도 저장하며 예약 모드 입력란을 덮어쓰지 않습니다. 탭 안의 **예약 조회** 버튼은 저장된 조회용 목록으로만 조회하고 예약용 정보를 저장하지 않습니다. 실패한 대상은 정상 0건으로 표시하지 않고 구분합니다. 일반 예약 대기 중에도 조회할 수 있지만 실제 예약 준비·실행 중에는 잠시 기다립니다.

**조회 대상** 선택과 **사이트 조회**는 조회 탭에 입력된 한 명의 이름·전화번호만 사용합니다. 다른 예약 모드의 이름·전화번호는 사용하지 않습니다. 선택칸은 필요한 너비만 사용하고 조회 버튼들과 정렬됩니다. 작은 화면에서는 글자를 억지로 줄이지 않고 간격을 유지해 줄바꿈합니다.

- **1개 예약 · 우선순위 방식**: 선택한 한 명으로 순위 중 객실 하나를 예약합니다.
- **여러 객실 동시 예약**: 선택한 한 명으로 체크한 객실들을 각각 예약합니다. 순위·드래그는 없습니다.
- **예약자별 동시 예약 · 우선순위**: 최대 5명의 개인별 순위를 입력하고 한 사람당 객실 하나를 예약합니다. 개인 순위는 이 모드에서만 사용합니다. 각 예약자는 독립 세션으로 함께 시작하며, 확실한 마감만 자기 다음 순위로 이동합니다. 불확실한 결과는 해당 예약자의 추가 제출을 중단하고 다른 예약자의 이미 시작된 실행은 독립적으로 진행됩니다.

동시 모드는 사이트가 허용하면 지정 시각 전에 정보 입력까지 마친 뒤 최종 제출을 진행합니다. 오픈 전 페이지에 객실 정보가 없거나 다음 단계 접근이 제한되면 그 예약자는 지정 시각에 처음부터 진행합니다. 서버 시간 동기화, 브라우저 처리·네트워크 지연 때문에 모든 요청의 서버 도착이나 예약 완료가 같은 밀리초일 수는 없습니다. 여러 사람의 순위에 같은 객실을 넣으면 서로 경쟁할 수 있으므로 다른 1순위를 권장합니다. 실제 예약·취소는 사용자 확인 후에만 실행하세요.
# 월별 전체 예약 현황 (2.0.0)

상단 플로팅 메뉴는 **☰ 현재 화면 이름**으로 표시됩니다. 가로 세 줄을 누르면 예약 모드·예약자 정보·예약 조회·월별 현황·로그 목록이 펼쳐지며 선택된 메뉴는 색상으로 구분됩니다. 메뉴 선택·바깥 클릭·Escape로 닫을 수 있고 스크롤해도 버튼이 유지됩니다.

한국 시간 기준 **지난 날짜는 개별 조회하지 않으며**, 달력에는 회색의 ‘지난 날짜·조회 제외’로 표시하고 예약 날짜로 선택할 수 없게 합니다. 이번 달은 오늘 이후의 날짜만 개별 조회합니다. 이전 달로 이동하면 월별 사이트 페이지와 개별 날짜 조회를 모두 생략합니다.

**월별 예약 현황** 탭을 누르면 한국 시간 **이번 달**을 기본으로 조회합니다. 제목 옆의 중복 버튼은 제거했습니다. 조회할 월을 직접 지정하고 **조회**를 누르거나 이전·다음 달 버튼을 이용할 수 있습니다. 달력 내부의 별도 스크롤 없이 한 달 내용을 페이지에 모두 펼칩니다. 휴대폰에서는 전체 페이지를 위아래로 스크롤해 볼 수 있습니다. 다른 탭으로 이동할 때 미등록 일정 입력은 초기화됩니다. 달력에서 날짜를 누르면 숙박 시작 날짜·링크·예약 오픈 시각에 반영하고 예약 매크로 화면의 날짜 입력 위치로 이동합니다. 날짜 선택만으로 저장이나 예약이 실행되지는 않습니다.

요일별 달력은 날짜마다 객실 목록을 표시합니다. 이름은 구역명을 빼고 해·샘·숲처럼 짧게 표시하며, 각 이름 옆에 초록 **가**(예약 가능), 빨강 **완**(예약 완료), 파랑 **대**(예약 대기), 갈색 **불**(1박 불가), 회색 **?**(확인 불가)를 붙입니다. 전체 이름과 상태는 각 객실 행의 도움말로 유지합니다. 표시 상태는 조회 시점의 정보이며, 실제 예약 성공이나 여러 박의 연속 예약 가능 여부를 보장하지 않습니다.

월별 페이지에 데이터가 없는 날짜는 `reservation1.php`의 개별 날짜 링크를 순차 조회합니다. 기본적으로 달력이 열려 있을 때만 조회하며 확인된 날짜부터 표시합니다. 개별 페이지에서도 확인할 수 없으면 **조회 실패 / 확인 불가**로 구분하고 가능·완료로 추정하지 않습니다. 사이트의 숙박 날짜를 검증해 다른 날짜의 객실 현황은 반영하지 않습니다. 예약 오픈 일시는 기존 숙박월 두 달 전 1일 00시 규칙으로 함께 표시합니다.

자동 예약 사전 준비·실행 중에는 월별 조회를 제한하며, 일반 객실 조회와 같은 독립 대기열을 사용해 예약 브라우저와 충돌하지 않습니다. 조회 창을 닫으면 일반 조회를 취소합니다. 실패 시 이전 달 결과를 최신 결과로 재사용하지 않습니다. **원본 월별 현황 사이트** 링크로 원본과 비교할 수 있습니다.

한국 시간 이번 달에서 3개월 뒤인 달만 HA 서버에서 주기적으로 미리 조회합니다. 2026년 10월에는 2027년 1월이며 11월에는 2027년 2월로 자동 변경됩니다. 그 이후 달은 기존 방식 그대로입니다.

# 여러 일정과 취소 자리 감시 (2.1.0)

우선순위는 **①·②·③** 동그라미 숫자로 표시합니다. 객실 목록·예약자별 순위·일정 요약·저장 이력·실행 확인창에 같은 표기를 사용하며 선택한 객실만 순위에 포함됩니다. 여러 객실 동시 예약과 취소 자리 감시는 순위가 없으므로 번호를 표시하지 않습니다. 표시만 변경되며 실제 예약 순서·저장 설정은 그대로 유지됩니다.

중지된 일정은 목록의 **수정**을 눌러 입력 화면에 불러올 수 있습니다. 수정 중에는 **예약/감시 일정 등록** 대신 **수정 저장**만 표시됩니다. 날짜·박수·객실·예약자·이름·감시 간격·마감 등을 변경한 후 저장하면 기존 일정이 갱신되며 새 일정은 생성되지 않습니다. 저장 후 목록의 **시작**을 눌러 재개하세요. **수정 취소** 또는 다른 탭 이동은 미저장 내용을 버리고 등록 모드로 돌아갑니다. 진행 중인 일정은 먼저 중지해야 하며, 완료·결과 확인 필요 일정은 예약확인 후 새 일정으로 등록해야 합니다. 기존 **설정 불러오기**는 새 일정 등록을 위한 복사 기능으로 유지됩니다.

1. 원하는 예약 모드에서 예약에 사용할 정보를 입력하세요. 예약자별 동시 탭만 여러 사람을 입력할 수 있습니다. 실제 예약과 별개로 조회하고 싶은 이름·전화번호는 **예약 조회** 탭에 저장하세요.
2. 원하는 예약 모드 탭에서 날짜·박수·객실 조건·실행 시각을 지정하세요. 예약자별 동시 모드에서는 각자의 객실 순위를 지정합니다.
3. 예약 실행 아래의 여러 일정 진행에서 일정 이름을 넣고 **예약 일정 등록**을 누르세요. 등록만으로 실행하지 않습니다. 목록의 **시작**을 누르고 최종 제출 안내에 동의하면 대기가 시작됩니다. 취소 자리 감시도 등록 후 목록에서 시작합니다. **예약 대기 시작** 버튼은 제거했으며, 실행 시각이 지났고 예약이 오픈된 경우에만 **지금 바로 예약**으로 독립 일정을 등록하면서 즉시 시작할 수 있습니다.
   등록이 성공하면 일정 이름·날짜·실행 시각·객실 선택·예약자 선택과 입력은 비워지고 박수는 1박, 감시 간격은 60초로 돌아갑니다. 예약자별 동시의 추가 입력란도 제거됩니다. 등록하지 않고 다른 탭으로 이동해도 초기화됩니다. 등록 실패 시에는 입력을 유지합니다. 이미 등록한 일정과 별도로 저장한 예약용·조회용 정보는 삭제하지 않으며, 목록의 **설정 불러오기** 또는 **저장된 예약자 선택**으로 다시 채울 수 있습니다. 일정 목록의 객실 조건은 ‘이름 : 해 → 달’처럼 예약자별로 표시합니다.
4. 다른 날짜나 모드로 바꿔 다음 일정을 등록하세요. 등록된 일정의 설정은 고정되어 편집 화면·예약자 저장·이력 불러오기로 바뀌지 않습니다. 저장 20개, 동시 진행 5개까지 지원합니다. 저사양 미니 PC에서는 1~2개부터 사용하고 CPU·메모리를 확인하세요. 각 모드 내부의 복수 객실 세션 때문에 실제 브라우저 작업 수는 일정 수보다 많을 수 있습니다.
5. 목록에서 개별 **중지**, **설정 불러오기**, **목록 삭제**를 사용할 수 있습니다. 실행 중인 설정을 바꾸려면 중지 후 불러와 새 일정으로 등록하세요. **모든 일정 중지**는 진행 중인 모든 일정을 중지합니다. 목록 삭제는 실제 예약 취소가 아니며, 감사·복구용 일정별 데이터 파일은 보존됩니다.

**취소 자리 감시** 탭에서는 숙박 날짜·박수·예약자 한 명을 지정하고 예약해도 되는 객실들을 체크하세요. **전체 선택·전체 해제**로 한꺼번에 지정할 수도 있습니다. 예약 방식, 예약 실행 시각, 객실 우선순위는 지정하지 않습니다. **감시 일정 등록**을 누른 뒤 목록에서 시작하면 감시합니다. 조회 간격은 60~3600초, 기본 60초입니다. 이는 이전 예약자의 취소 이력을 수집하는 기능이 아니라 설정 조건으로 예약 가능한 자리가 생겼는지 조회하는 기능입니다.

- 체크한 객실 중 **하나라도** 날짜·박수 조건에 맞게 예약 가능하면 선택한 예약자 한 명으로 **객실 하나**를 즉시 예약합니다. 다른 체크 객실이 마감이어도 기다리지 않습니다.
- 객실 선호 순위 없이 사이트에서 확인된 객실 목록을 기준으로 하나를 선택합니다. 다른 예약자나 다른 일정도 감시하려면 별도 감시 일정을 등록하세요.
- 오픈 전에는 공식 오픈 시각 이후부터 조회합니다. **감시 마감 날짜·시각**을 비워두면 숙박 시작일 **00:00:00**에 종료하며 당일에는 예약하지 않습니다. 예: 11월 7일 숙박이면 11월 7일 00시에 종료합니다.

- 조회 오류·날짜 불일치·미확인·다른 박수 불가는 예약하지 않으며 조회 오류가 반복되면 간격을 최대 8배까지 늘립니다.
- 가능 상태가 확인되면 즉시 예약을 시도하지만 조회 간격·통신 지연·경쟁 예약 때문에 성공은 보장되지 않습니다. 최종 제출 직전에도 기존 엔진의 날짜·객실 검증을 적용합니다.
