# 결제 수단 추가 후 단독·다인·다중 예약 점검 · 2026-11-05

## 결론과 범위

현재 공식 폼의 `pay_method`는 `bank`(무통장입금), `card`(신용카드), `iche`(실시간 계좌이체) 라디오 선택입니다. 배포 중인 애드온 2.15.39 / Android 0.4.31의 처리 방식은 bank 값을 명시적으로 찾고 선택하므로, 현재 추가된 두 수단 때문에 발생하는 입력·결제 선택 오류는 발견하지 못했습니다. 기능 코드·APK·업데이트 메타데이터는 변경하지 않습니다.

실제 공식 페이지에서 입력·필수 약관·기간/사이트·무통장 선택·제출 버튼 준비 상태까지 확인했습니다. 최종 제출 및 예약 완료 영수증 검증은 수행하지 않았으므로 서버의 최종 접수 성공이나 결제 완료를 확인한 것으로 해석하지 않습니다. 실제 예약·취소·입금은 하지 않았습니다.

## 공식 화면의 읽기 전용 검사

- 2027-01-27 입실 / 01-28 퇴실, 1박, 성인 2명. 그 시점에 조회 가능한 해_하늘존·달_하늘존을 사용했습니다. 실제 저장 예약자 대신 모의 한글 이름·모의 번호를 입력했습니다.
- 단독: 한 명·한 사이트, 다중: 한 명·두 사이트, 다인: 두 명·각각 다른 사이트. 애드온의 실제 모드 분배 코드를 실행하되 모든 자식 세션의 runSingle에 checkOnly를 강제하고 상태 저장은 격리된 메모리 객체로 처리했습니다. 모드 분배 코드 내부의 완료 집계는 실제 예약 완료 증거가 아닙니다.
- 총 5개 독립 폼 세션에서 bank/card/iche를 각각 먼저 선택한 다음 앱과 애드온의 입력·검증 함수를 호출했습니다. 15개 초기 선택 조건, 양쪽 공통 폼 검증 모두 통과했습니다. 카드·계좌이체 선택 시 숨겨지는 입금자 필드도 무통장 전환 후 정상이며, 선택값은 FormData에서 bank 한 개만 남았습니다.
- 필수 약관·예약자 입력 형식·사이트명/URL/사이트 번호·입실/퇴실/인원·CSRF 존재 확인, 유효성 검사 통과. 최종 버튼 1개·활성화·예약 신청하기 표시·formaction 변경 없음까지 확인하되 클릭하지 않았습니다.
- 앱 JavaScript는 현재 공식 화면 DOM 위에서 prepare/preflight를 직접 호출했습니다. Android 실기기의 전체 WebView/서비스 실행을 원격으로 확인한 검사는 아닙니다. Android 배치 작업의 예약자·전화번호·사이트 분리 구성은 별도 JVM 검사로 확인했습니다.
- 최종 제출 이벤트 0, 비 GET/HEAD 요청 시도 0, 예약 제출 기록 생성 0. 초기화 스크립트의 submit 이벤트 차단, 네트워크의 비 GET/HEAD 차단, booking record writer 거부를 함께 적용했습니다. HA 운영 일정·예약자·알림·예약 기록을 수정하지 않았습니다.

## 회귀 검사

- Node 46개 통과: 현재 세 라디오 값과 입금자 필드 숨김/표시, 카드·iche 기본 선택에서 bank 전환, bank 누락 거부, 제출 직전 다른 수단으로 변경 시 무단 보정·클릭 금지, 다중 예약자의 선택/분리, 다인 동시 작업 및 최종 제출 간격/실패 처리, 기존 단일 제출·영수증 검증 회귀를 포함합니다. 이 중 제출 검사는 모의 사이트 응답을 사용합니다.
- 기존 multiple-profile 테스트 자료에 숫자가 든 예약자명이 남아 한글 이름 규칙에 실패했습니다. 이름만 예약자일/이/삼/사/오로 맞추고 네 번째 선택자의 기대값을 예약자사로 수정했습니다. 운영 이름 검증을 완화하지 않았습니다.
- Android JVM 69개 통과. 신규 두 검사는 다중의 한 예약자가 각 사이트 작업에 유지되는지, 다인의 예약자/번호/입금자/사이트가 예전 루트 예약자로 덮이지 않는지 확인합니다. 테스트 과정에서 실제 앱 서비스를 시작하지 않았습니다.

## 재현

실제 사이트 검사는 자동 테스트에서 실행하지 않는 별도 opt-in 스크립트입니다. 명시적으로 환경 변수를 지정해야 하며 제출 코드는 호출하지 않습니다.

```sh
cd swim_reservation
SWIM_LIVE_READONLY=1 SWIM_CHECK_DATE=2027-01-27 CHROMIUM_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' node test/live-payment-readonly.js
```

결과 파일은 `/tmp/swim-live-payment-readonly-report.json`이며 사이트/결제 옵션/검증 결과만 포함합니다. 세션 토큰·CSRF 값·입력한 개인정보 원문은 출력하지 않습니다. 날짜가 지났거나 빈자리가 부족하면 새로운 열린 날짜를 지정해야 합니다.
